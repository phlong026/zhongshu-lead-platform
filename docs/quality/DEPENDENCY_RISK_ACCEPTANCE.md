# V1.2 依赖风险临时接受：PYSEC-2026-3552

- 风险编号：`PYSEC-2026-3552`
- 别名：`CVE-2026-69247` / `GHSA-g6cj-pr64-35w5`
- 依赖：`cryptography==49.0.0`
- 建档日期：2026-08-07
- 状态：**临时接受，严格限定范围**
- 最迟复核日期：**2026-08-21**
- 自动解除条件：`cryptography 50.0.0` 或其他官方修复版本正式发布后，立即升级并删除 CI 豁免；正式全量生产 Go/No-Go 前必须再次检查，即使尚未到复核日期。

## 1. Advisory 影响面

该 advisory 影响 `cryptography` 的 PKCS#7 EnvelopedData 解密路径，包括：

- `pkcs7_decrypt_der`
- `pkcs7_decrypt_pem`
- `pkcs7_decrypt_smime`

攻击成立需要应用对攻击者可控的 PKCS#7 EnvelopedData 做私钥解密，并向攻击者提供可区分错误/时序反馈，典型场景是 S/MIME 网关或邮件过滤器。

## 2. 当前项目暴露面核对

当前 V1.2 不提供 PKCS#7 / S/MIME 解密能力，也不调用任何 `pkcs7_decrypt_*` API。手机号等字段加密使用 `cryptography.fernet.Fernet`；手机号去重使用 Python 标准库 HMAC-SHA256。

因此，当前应用代码不存在该 advisory 描述的可触发入口。该结论只适用于当前代码树；任何引入 PKCS#7 解密 API 的变更都必须先删除本风险接受并重新评审。

## 3. 为什么不能直接升级修复

`pip-audit` 当前将修复版本标记为 `50.0.0`，但截至本记录，项目可安装的正式稳定版本仍为 `49.0.0`，`50.0.0` 尚未作为正式稳定版本发布。因此不能在发布依赖中伪造、预设或强行安装不存在/未正式发布的修复版本。

## 4. 临时控制

在修复版本正式发布前，仅允许对 **`PYSEC-2026-3552` 这一条 ID** 使用 `pip-audit --ignore-vuln PYSEC-2026-3552`。其余任何依赖漏洞仍必须使 PR/Release CI 失败。

同时执行以下补偿控制：

1. 自动测试扫描 `apps/` 与 `scripts/`，禁止出现 `pkcs7_decrypt_`；
2. `cryptography` 固定到当前正式稳定版本，不允许降级；
3. 安全审计报告、生产检查表和发布包必须包含本风险接受记录；
4. 正式全量开放前重新查询该 advisory 和可安装版本；
5. 一旦 50.0.0 或官方等效修复稳定版可安装，立即升级、运行完整 CI，并删除此豁免。

## 5. 失效条件

出现下列任一情况，本风险接受立即失效并转为 `NO-GO`：

- 代码引入任何 `pkcs7_decrypt_*`、S/MIME/PKCS#7 私钥解密入口；
- advisory 的影响范围扩大到当前使用的 Fernet 路径；
- 官方修复版本已正式发布但项目仍未升级；
- 新增安全信息表明当前补偿控制不足；
- 到 2026-08-21 仍未完成复核。

## 6. 上线判定

本记录只允许代码门禁在当前不可修复版本窗口内继续执行，不表示漏洞不存在，也不替代正式生产安全签字。目标环境 Go/No-Go 必须再次核实：修复版本是否已发布、当前代码是否仍无受影响 API、CI 是否只豁免该单一 advisory。
