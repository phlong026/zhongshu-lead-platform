# 众墅之家客资平台 P0 测试与质量报告

- 发布候选版本：`v1.0.0-p0`
- 报告日期：2026-08-01
- 代码基线：PRD V1.0·执行版 / 详细开发计划 V1.0
- 测试环境：Python 3.13、SQLite 隔离数据库、FastAPI TestClient、Node.js JavaScript 语法检查

## 1. 质量结论

当前代码形成了可运行的 P0/MVP 基线，核心业务闭环已经通过服务级与 HTTP 级自动测试：

```text
飞书/模拟导入 → 暂存与去重 → 电销核验 → 合格客资池
→ 运营人工派发 → 加盟商领取扣积分 → 跟进
→ 截图+录音退回举证 → 管理员审核 → 返还积分
```

本报告不等同于生产环境上线认证。真实微信公众号、飞书、生产 PostgreSQL、私有对象存储、域名 HTTPS 与业务数据仍需按上线 Gate 完成联调和验收。

## 3. HTTP 全链路验收

`apps/api/tests/test_http_e2e.py` 使用独立数据库和私有临时存储验证：

1. 运营角色看不到财务指标和加盟商具体积分余额；
2. 老板角色可查看财务积分汇总；
3. 合格客资可筛选符合地区、类目、品牌及积分资格的加盟商；
4. 人工派发后，加盟商领取前只能看到脱敏手机号；
5. 领取、扣积分、流水和联系方式解锁一次完成；
6. 跟进记录不可覆盖，只能追加；
7. 退回申请必须上传沟通截图和电话录音；
8. 审核通过后，订单退回、客资释放和积分返还一致完成；
9. 扣分流水与返分流水正确关联；
10. 关键动作写入审计日志。

## 4. 关键风险测试

| 风险 | 已实施控制 | 验证方式 |
|---|---|---|
| 重复导入 | 飞书记录唯一键、手机号哈希、疑似重复关系 | 导入幂等测试 |
| 重复派发 | 客资当前派发 ID、事务锁、派发幂等键 | 派发服务测试与 HTTP 测试 |
| 重复领取/扣分 | 订单锁、领取流水业务唯一性、幂等键 | 领取幂等测试 |
| 余额透支 | 条件扣减、积分不足错误 | 积分服务测试 |
| 重复返积分 | 退回状态锁、返分业务唯一键、关联原扣分流水 | 退回服务与 HTTP 测试 |
| 财务字段泄露 | 服务端角色投影，不依赖前端隐藏 | 角色看板与候选加盟商 HTTP 测试 |
| 证据公开访问 | 私有对象存储、短时签名令牌、角色校验 | 存储及接口契约检查 |
| 超时提醒重复 | 通知存在性检查 + Outbox 事件唯一键 | 定时作业幂等测试 |
| SQLite 时区差异 | 比较边界统一规范化为 UTC | 时区单元测试与 HTTP 全链路测试 |

## 5. 尚未在本构建环境完成的验证

以下项目必须在真实部署环境完成，当前不能虚构为已通过：

- 企业认证服务号的网页授权、消息能力、模板/服务通知额度和回调验签；
- 飞书企业自建应用的真实多维表格权限、分页、限流和状态回写；
- PostgreSQL 生产实例上的并发压测、锁等待与备份恢复演练；
- 腾讯云 COS、阿里云 OSS 或兼容 S3 私有存储的真实上传与签名下载；
- Docker Compose 在目标云服务器上的完整启动验证（本构建环境未提供 Docker）；
- iOS/Android 不同微信版本的文件选择、录音上传和弱网恢复；
- 安全渗透测试、隐私影响评估及电话录音业务合规确认。

## 6. 上线建议

生产上线至少满足：

1. 微信 Gate 0 与飞书字段映射签字；
2. 充值档位、积分价格、24/48 小时规则和退回原因版本冻结；
3. PostgreSQL 迁移、备份和恢复演练通过；
4. 真实微信和飞书联调通过；
5. 至少 2 家灰度加盟商连续试运行 3～5 个工作日；
6. P0 UAT、权限回归、积分对账和证据访问测试全部通过；
7. 生产密钥全部由环境变量或密钥管理服务注入。
