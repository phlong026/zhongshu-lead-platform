# V1.2 Hardening H02：生产 Demo 凭据与演示登录清理评审

- Hardening Issue：#51
- 父任务：#49
- 分支：`fix/v1.2-h02-demo-credentials`
- 风险等级：P1
- 当前状态：实现完成，等待 PR CI / Codex Review

## 问题基线

上线前综合评审发现生产静态页面仍暴露开发/演示便利信息：

- 管理后台登录页预填 `admin / Admin123!`；
- 管理后台显示“演示账号见项目文档”；
- 新建内部账号预填 `ChangeMe123!`；
- 加盟商 H5 显示“本地演示环境”，并预填 `franchise_demo / Franchise123!`；
- H5 提供直接账号密码“进入演示”入口。

即使生产数据库不 seed 对应账号，这些信息也不应出现在正式静态资源和用户界面中。

## 本次修复

1. 管理后台登录账号与密码均改为空输入，只有提示文案，不再预填任何 credential；
2. 删除管理后台“演示账号见项目文档”生产可见提示；
3. 新建内部账号的初始密码改为空输入，要求管理员显式设置高强度初始密码；
4. H5 登录页删除本地演示分区、用户名/密码字段、Demo 登录按钮和直接 `/auth/login` 演示回调；
5. H5 未登录页面只保留真实微信授权入口与专属邀请提示；
6. H5 个人中心登录方式统一显示“微信授权”；
7. 新增 `test_v12_hardening_demo_credentials.py`，扫描 admin/H5/call-H5 生产静态文本资源，禁止已知 Demo/default credential 和 Demo 登录标记重新出现；
8. 保留既有 `SEED_DEMO=false` 生产配置门禁；测试/开发数据库的 demo seed 不属于生产静态资源，不在本 PR 删除。

## PR 边界

本 PR 只处理生产静态资源中的 Demo/default credential、演示账号提示与演示登录入口。

不包含：

- 登录专项限流、失败锁定、MFA、raw JWT 响应治理（#52 H03）；
- 删除所有 V1.0.1 Legacy 页面（H01 已将其写路径在生产硬阻断）；
- 测试 fixture/demo seed 的整体重构。

旧 Legacy 管理页仍存在“导入演示客资”等历史开发功能文案，但其生产 mutation 已由 H01 `LEGACY_WRITE_ENABLED=false` 后端硬门禁返回 410；该文案不包含 Demo credential 或登录能力，不作为 H02 的范围扩张项。

## 自评审

- Admin 登录仍走正式 `/auth/login`，只是去掉默认值；
- H5 正式登录继续走 `/auth/wechat/start`，邀请参数与 OAuth 链路未改变；
- 未修改认证服务、Token、RBAC、数据库模型或业务状态机；
- 静态门禁覆盖三个生产 public root，后续若重新加入已知 Demo/default credential 将直接导致 pytest 失败。
