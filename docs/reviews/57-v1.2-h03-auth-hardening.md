# V1.2 Hardening H03：内部账号认证加固评审

- Hardening Issue：#52
- 父任务：#49
- 分支：`fix/v1.2-h03-auth-hardening`
- 风险等级：P1
- 当前状态：第一版实现完成，等待 PR CI / Codex Review

## 问题基线

内部管理账号已经使用 Argon2 + JWT + HttpOnly Cookie，但上线前评审确认仍存在以下生产风险：

1. `/api/v1/auth/login` 只有通用 API 级 20r/s 限流，缺少登录专项来源 IP 防护；
2. 内部账号没有持久化失败次数和临时锁定，凭据填充/暴力尝试可长期持续；
3. 登录失败、锁定、恢复缺少集中安全审计；
4. 浏览器登录同时把 JWT 放入 HttpOnly Cookie 和 JSON 响应，JavaScript 没有必要接触 raw token；
5. 生产后台网络访问边界未形成独立 Runbook。

## 本次设计

### 账号级保护

新增独立 `auth_login_state` 表，一对一保存：

- `failed_count`；
- `last_failed_at`；
- `locked_until`。

默认规则：15 分钟失败窗口内 5 次失败，锁定 15 分钟。内部认证先 `SELECT User ... FOR UPDATE`，在 PostgreSQL 下串行化同账号并发失败，保证多 API 实例共享一致锁定状态。

### IP 级保护

Nginx 为 `/api/v1/auth/login` 建立独立 `auth_login_limit`：`10r/m`、`burst=5`、超限返回 429。账号级数据库锁定与来源 IP 限流分别覆盖用户名攻击与来源攻击。

### 浏览器会话

登录成功后 JWT 只写入 `access_token` Cookie：HttpOnly、production Secure、SameSite=Lax、Path=/。登录 JSON 只返回 user 摘要，不返回 raw JWT。

为了保留多角色 HTTP E2E，测试从响应 Set-Cookie 中读取 token 再构造 Bearer header；没有新增仅供测试使用的生产 token endpoint。

### 审计

新增/使用事件：

- `AUTH_LOGIN_FAILED`；
- `AUTH_LOGIN_LOCKED`；
- `AUTH_LOGIN_BLOCKED`；
- `AUTH_LOGIN_UNLOCKED`；
- `AUTH_LOGIN`；
- `AUTH_LOGOUT`。

失败计数与审计在异常响应前显式 `db.commit()`，防止认证异常导致安全状态回滚。审计只记录 user_id、failure_count、locked_until、reason code、request_id、IP、User-Agent，不记录密码、raw JWT 或 Cookie。

## 关键安全边界

- 不存在用户名执行 Argon2 dummy verify，保持与真实密码路径的计算成本更接近；
- 锁定期内正确密码也不能绕过；
- 锁定到期后自动清理状态并记录 `AUTH_LOGIN_UNLOCKED`；
- 账号 DISABLED 后旧 Cookie/Bearer 均由现有 principal 校验立即拒绝；
- logout 增加 `session_version`，此前 Bearer token 即刻失效；
- 生产 `/admin` 优先 VPN/IP 白名单/WAF/零信任可信入口，Nginx 限流只是纵深防御。

## 数据与迁移

新增 Alembic revision `0005_auth_login_hardening`，基于 `0004_v12_reward_snapshot` 创建 `auth_login_state` 及 `locked_until` 索引。

独立安全状态表避免把登录风控字段混入业务 `users` 表，降低认证加固对既有用户模型和 V1.0.1/V1.2 业务数据的耦合。

## 自动测试

新增/调整测试覆盖：

- 登录 JSON 无 token，Cookie 为 HttpOnly + SameSite=Lax；
- production Cookie 带 Secure；
- 前 4 次错误 401，第 5 次 429 并持久锁定；
- 锁定期正确密码仍 429；
- 锁定到期后正常恢复并清空失败状态；
- 失败/锁定/阻断/恢复/成功均有审计；
- 密码与 JWT 不进入认证审计；
- DISABLED 用户旧 Cookie 立即失效且不可重新登录；
- logout 后旧 Bearer token 因 `session_version` 失效；
- 不存在用户名保持统一 `AUTH_LOGIN_FAILED`；
- Nginx 存在独立登录 rate-limit zone/location/429；
- migration 处于当前 Alembic 链；
- 原多角色 HTTP E2E 改用 HttpOnly Cookie 中的 token，不依赖 JSON token。
