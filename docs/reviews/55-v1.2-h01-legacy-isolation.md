# V1.2 Hardening H01：Legacy 写路径隔离评审

- Hardening Issue：#50
- PR：#62
- 分支：`fix/v1.2-h01-legacy-isolation`
- 风险等级：P1
- 当前状态：核心修复与 3 个 Codex P1 已完成，最新代码门禁通过；等待本评审文档 head 的最终 CI 后合并

## 问题基线

V1.2 已实现新的录客、人工派发、领取、3 工作日退回与 `RETURN_VERIFY`，但 V1.0.1 的 `/admin/`、`/h5/` 默认页面及 `/leads`、`/verification`、`/dispatch`、`/claims`、`/returns` mutation API 仍可创建旧业务事实，存在 48 小时退回、截图+录音 AND、前置核验等规则被误用风险。

## 最终修复

1. 新增 `LEGACY_WRITE_ENABLED`；开发/测试需要历史 mutation 回归时显式开启，生产固定为 `false`；
2. `LegacyWriteGuardMiddleware` 以 `LEGACY_WRITE_ENABLED` 为唯一运行时门禁：只要为 `false`，无论 `APP_ENV` 是否误标，Legacy mutation 均返回 `410 LEGACY_WRITE_DISABLED`；
3. production Compose 对 API / Scheduler 同时固定 `APP_ENV=production`、`LEGACY_WRITE_ENABLED=false`，形成部署层与运行时双重保护；
4. Legacy GET / HEAD / OPTIONS 保留，历史数据仍由原 RBAC/租户权限保护；
5. `/admin/`、`/h5/` 先验证 Cookie JWT、用户 ACTIVE 与 `session_version`：有效会话进入 V1.2，未登录/失效会话进入真实登录/OAuth 页面，避免 V1.2 页面认证失败后的重定向循环；
6. `/admin/legacy`、`/h5/legacy` 保留为显式历史页面入口，但生产 Legacy mutation 已由后端硬门禁阻断；
7. 新增 `run_assignment_timeouts_v12()`：仅处理 `Lead=DISPATCHED` 且 `current_assignment_id` 指向同一 `PENDING_CLAIM` Assignment 的 V1.2 待领取单；过期后 Assignment→`EXPIRED`、Lead→`READY_DISPATCH`，并清空 `current_assignment_id`；
8. Scheduler 在 `LEGACY_WRITE_ENABLED=false` 时仅运行 V1.2 timeout job，不再调用会把客资写回旧 `QUALIFIED` 的 `run_assignment_timeouts()`；
9. V1.2 timeout job 不改写 Legacy `QUALIFIED/PENDING_CLAIM` 历史单；
10. 增加 Legacy 分类、APP_ENV 误标 fail-closed、会话入口、V1.2 timeout/Legacy 非误伤、Scheduler 路由等回归测试；
11. 更新冲突登记与 Legacy Isolation Runbook。

## Codex 首轮发现与处置

### P1-01 APP_ENV escape hatch

首轮实现只有 `APP_ENV=production AND LEGACY_WRITE_ENABLED=false` 才阻断旧写接口，存在环境标签误配置导致门禁失效的风险。

处置：去除 `APP_ENV` 条件；`LEGACY_WRITE_ENABLED=false` 即无条件 fail-closed。同时 production Compose 固定 `APP_ENV=production`。对应 Thread 已回复并 resolved。

### P1-02 Scheduler 仍执行旧 timeout

首轮实现只拦 HTTP mutation，但 Scheduler 仍直接运行旧 `run_assignment_timeouts()`，可能把 V1.2 过期客资写成旧 `QUALIFIED`，使其从 V1.2 `READY_DISPATCH` 派发池消失。

处置：新增 V1.2-aware timeout job；生产/Legacy-disabled Scheduler 改跑新 job，并新增状态回池及 Legacy 非误伤测试。对应 Thread 已回复并 resolved。

### P1-03 未登录入口重定向循环

首轮将 `/admin/`、`/h5/` 无条件重定向到 V1.2 页面，而 V1.2 页面认证失败会返回 `./`，形成循环。

处置：默认入口改为服务端验证有效 session；未登录/无效 session 进入真实登录页，有效 session 才进入 V1.2。对应 Thread 已回复并 resolved。

## 非误伤检查

- V1.2 核心 mutation 使用 `/api/v1/v1.2/...`，不属于 Legacy 前缀；
- 认证、用户、公司、积分、跟进、通知等 V1.2 仍复用的基础能力不被统一关闭；
- 历史表、模型和 Legacy GET 未删除，迁移、审计、对账仍可追溯；
- V1.2 timeout 只处理满足 V1.2 lead/assignment 不变量的记录，不扫描改写普通 Legacy 待领取单；
- 生产故障不得通过重新开启 `LEGACY_WRITE_ENABLED=true` 回退旧业务规则，应执行 V1.2 回滚 Runbook。
