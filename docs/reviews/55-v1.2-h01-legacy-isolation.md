# V1.2 Hardening H01：Legacy 写路径隔离评审

- Hardening Issue：#50
- 分支：`fix/v1.2-h01-legacy-isolation`
- 风险等级：P1
- 当前状态：实现完成，等待 PR CI / 最终 Review

## 问题基线

V1.2 已实现新的录客、人工派发、领取、3 工作日退回与 `RETURN_VERIFY`，但 V1.0.1 的 `/admin/`、`/h5/` 默认页面及 `/leads`、`/verification`、`/dispatch`、`/claims`、`/returns` mutation API 仍可创建旧业务事实，存在 48 小时退回、截图+录音 AND、前置核验等规则被误用风险。

## 本次修复

1. 新增 `LEGACY_WRITE_ENABLED`，开发/测试默认允许历史回归，production 强制为 `false`；
2. `validate_production_settings()` 在生产发现 Legacy 写开关打开时直接判定无效；
3. production Compose 对 API / Scheduler 显式固定 `LEGACY_WRITE_ENABLED=false`；
4. 新增 `LegacyWriteGuardMiddleware`：生产环境对 Legacy mutation 返回 `410 LEGACY_WRITE_DISABLED`；
5. Legacy GET / HEAD / OPTIONS 不受该门禁影响，历史数据继续由原 RBAC/租户权限保护；
6. `/admin/` 默认进入 `v12-operations.html`；
7. `/h5/` 默认进入 `v12-workbench.html`；
8. `/admin/legacy`、`/h5/legacy` 作为显式历史只读页面入口；
9. 新增生产校验、路由、Legacy mutation、V1.2 非误伤回归测试；
10. 更新冲突登记与生产 Legacy 隔离 Runbook。

## 自评审重点

### V1.2 新流程非误伤

V1.2 运营台核心 mutation 使用 `/api/v1/v1.2/...`，不属于 Legacy 前缀。认证、用户、公司、积分、跟进、通知等未被本门禁统一关闭，避免误伤仍被 V1.2 复用的基础能力。

### 历史只读兼容

本次没有删除旧表、旧模型或 Legacy GET，因此历史迁移、审计和对账仍可追溯。生产只禁止继续生成旧业务事实。

### 回滚边界

生产故障不得通过重新设置 `LEGACY_WRITE_ENABLED=true` 回退到旧业务规则；应冻结相关入口并执行 V1.2 回滚 Runbook。
