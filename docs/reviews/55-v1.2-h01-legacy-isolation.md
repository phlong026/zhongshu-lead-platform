## 问题基线

V1.2 已实现新的录客、人工派发、领取、3 工作日退回与 `RETURN_VERIFY`，但 V1.0.1 的页面、HTTP mutation、定时作业及手工运维入口仍可能继续创建或改写旧业务事实，存在前置核验、48 小时退回、截图+录音 AND、旧 `QUALIFIED` 状态回写等规则与 V1.2 并存的风险。

## 最终修复

1. 新增 `LEGACY_WRITE_ENABLED`；开发/测试需要历史 mutation 回归时显式开启，生产固定为 `false`；
2. `LegacyWriteGuardMiddleware` 以 `LEGACY_WRITE_ENABLED` 为唯一运行时门禁：只要为 `false`，无论 `APP_ENV` 是否误标，Legacy HTTP mutation 均返回 `410 LEGACY_WRITE_DISABLED`；
3. production Compose 对 API / Scheduler 同时固定 `APP_ENV=production`、`LEGACY_WRITE_ENABLED=false`；
4. Legacy GET / HEAD / OPTIONS 保留，历史数据继续受原 RBAC/租户权限保护；
5. `/admin/`、`/h5/` 校验 Cookie JWT、用户 ACTIVE 与 `session_version`：有效会话进入 V1.2，未登录/失效会话进入真实登录/OAuth 页面；
6. `/admin/legacy`、`/h5/legacy` 保留为显式历史页面入口，但不能绕过后端 Legacy 写门禁；
7. 新增 `run_assignment_timeouts_v12()`：只处理满足 V1.2 `Lead=DISPATCHED + current_assignment_id` 不变量的待领取单；过期后 Assignment→`EXPIRED`、Lead→`READY_DISPATCH`；
8. 新增统一 `run_assignment_timeouts_active()`；daemon `scripts/scheduler.py` 与手工 `scripts/run_jobs.py assignment-timeouts/all` 都只能通过该入口选择当前业务版本；
9. V1.2 timeout 候选仅查询 ID，锁定后使用 `populate_existing=True` 强制刷新 Assignment/Lead 并重新检查状态，避免多 Scheduler 并发重复提醒；
10. V1.2 跟进逾期通知使用 `/h5/v12-workbench.html?view=assignments&id=...`；Legacy 保留旧 hash，并兼容旧 deep-link 去重；
11. `feishu_sync_service.fetch_and_import_feishu()` 与 `writeback_feishu_results()` 同样受 `LEGACY_WRITE_ENABLED` 控制，因此 HTTP、手工 Job 或直接 service 调用均不能在生产恢复 V1.0.1 飞书新增客资；
12. 增加对应配置、会话、状态回池、并发刷新、通知深链、手工作业分流和飞书 direct-service 回归测试；
13. 更新冲突登记与 Legacy Isolation Runbook。
