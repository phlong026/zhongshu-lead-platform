## 三、代码与业务边界复核

1. H5 仍采用微信 OAuth、公司级绑定和消息深链，不增加手机号登录、App 或小程序。
2. 领取前只展示脱敏客资；领取成功后在原子积分事务完成后解锁完整电话。
3. 现金交易继续在线下完成，后台人工充值积分；未增加在线支付入口。
4. 退回申请继续要求聊天截图和电话录音双证据，管理员审核通过后仅返还领取时实际扣除积分一次。
5. 运营人工派发只展示可派、积分不足、未绑定微信、停用和类目不匹配等资格标签，不展示具体积分余额。
6. 管理后台角色、接口、数据范围和字段投影继续由后端 RBAC 控制，前端视觉层不授予权限。
7. ADM-05 增加任务分配和回收；回收仅允许 `PENDING` / `ASSIGNED` 并写审计日志。
8. ADM-10 公司详情仅按 `company.read` 返回；积分余额继续由 `points.read` 控制。
9. ADM-16 使用版本化字典接口；ADM-17 仅展示真实角色权限和敏感权限。

## 四、联合复核发现并修复的问题

### 1. H5 无效深链被加载状态覆盖

- 问题：深链失败后，H5-19 加载增强层覆盖 H5-18 安全失效内容。
- 修复：安全失效内容优先识别和渲染，成功后停止深链加载层。
- 结果：页面明确显示“该链接已失效”，且不展示任何客资摘要。
- 修复 PR：#22。

### 2. 运营看板误标为老板看板

- 问题：运营说明文字中包含“财务”字样，整页文字扫描导致页面 ID 误判。
- 修复：只依据真实财务指标卡标签识别 ADM-02；无财务指标时识别 ADM-03。
- 结果：运营工作台正确显示 ADM-03，且不出现积分总余额、累计充值等财务指标。
- 修复 PR：#23。

## 六、视觉复核说明

当前执行环境中的 Chromium 被策略禁止访问 localhost，因此联合视觉复核采用：

1. 本地 FastAPI 服务生成真实、当前演示数据的 API 响应；
2. Chromium 直接加载 Release 中最终 HTML、CSS、JavaScript；
3. 将上述 API 响应注入页面完成离线浏览器渲染；
4. 逐路由截图并核对页面 ID、布局、角色字段和关键文案。

这些截图是最终前端源码的浏览器渲染结果，但不是生产服务器或真实微信公众号环境截图。
