## 2. 发现问题与修复（本次提交）

### M-A：confirm-start 限流双重缺陷（Medium，已修复）

`routers/auth.py` `_confirm_start_rate_limited`：

1. **无锁读改写**（Phase03 记录登记的 M1 待修项，`git log -S "Lock()"` 全历史确认从未落地）：`def` 端点跑线程池（默认 40 tokens），并发 burst 下多线程同时读到旧计数同时通过检查，同 (invite, IP) 一个窗口内放行远超 10 次——限流可被绕过。
2. **fail-closed 桶表武器化**：随机 invite 串（16–128 字符任意值）每个生成一个 invite+IP 桶，填满 4096 桶后 fail-closed 拒绝一切新键。经核算 nginx `/api/` 20r/s 限流下单 IP 60s 窗口内最多送达约 1200 请求（< 4096），但 4+ 个分布式源 IP 协同即可填满，且若 M-B 未修（所有请求 IP 恒为 nginx 内网地址）攻击面进一步放大——新用户微信绑定确认入口可被无限期全站阻断。

**修复**：
- `_CONFIRM_START_LOCK`（`threading.Lock`）串行化全部桶操作；原函数拆为持锁包装器 + `_confirm_start_rate_limited_locked` 纯内存实现（锁内无 I/O、无嵌套锁）。
- 新增 `_CONFIRM_START_IP_BUCKETS` 单 IP 维度独立限流（60s 窗口 30 次、4096 桶上限、同 fail-closed 策略）：IP 键空间由 TCP 对端或受信反代决定，无法凭请求体伪造，单 IP 能创建的 invite 桶被硬性封顶。
- 同源加固：`_callback_audit_throttled`（N11 审计节流）读改写同样纳入该锁，消除同类竞态（fail-open 语义不变）。
- 测试锁定：`test_confirm_start_ip_dimension_caps_bucket_creation`（单 IP 30 个不同 invite 放行、第 31 次拒绝、其他 IP 不受拖累）、`test_confirm_start_rate_limit_is_thread_safe`（60 并发同键恰好放行 10）；conftest autouse fixture 同步清理新桶。

### M-B：TRUST_PROXY_HEADERS 生产配置未暴露（Medium，已修复）

`_request_ip` 依赖 `settings.trust_proxy_headers`（默认 False，方向正确），但该开关在 `docker-compose.prod.yml`、`.env.example`、`.env.docker.example`、`docker/prepare-env.sh`、`scripts/validate_production_env.py` 中全部无登记。生产 nginx 模板对所有代理路径固定 `proxy_set_header X-Real-IP $remote_addr` 强制覆写——恰好满足开启条件却无人提示开启。按现状部署：全部审计行（登录/绑定/回调溯源/INVITE_CONFIRM_START）的 IP 恒为 nginx 容器内网地址，安全事件无法溯源（静默失败），且 N11 节流键与限流键的 IP 分量对全体用户恒定。

**修复**：
- `docker-compose.prod.yml` api 与 scheduler 服务均固定注入 `TRUST_PROXY_HEADERS: "true"`（生产拓扑 nginx 必然前置，fail-safe 硬编码；scheduler 同步注入避免与 api 形成不对称的启动校验依赖）。
- `production.py` `validate_production_settings` 新增校验：必须显式 `true`/`false`（缺省报错），生产一律要求 `true`（设 `false` 报错并说明原因）；容器 entrypoint 与部署机 `validate_production_env.py` / `verify_production.py` / `preflight_v12.py` 调用链全部生效。
- `.env.example`（默认 false + 适用条件注释）、`.env.docker.example`（生产样例 true）、`docs/runbooks/DEPLOYMENT.md`（配置校验节新增说明）同步登记。
- 测试锁定：`test_production_validation_requires_explicit_trust_proxy_headers`（缺省/false/yes/1 全部拒绝）、部署文件契约断言（compose 必含 `TRUST_PROXY_HEADERS: "true"`）。

### 复评结论（CodeReview 子代理二审）
