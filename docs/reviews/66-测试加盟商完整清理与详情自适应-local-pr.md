## 一、确认后的业务合同

1. 加盟商在创建时可由用户明确标记为测试主体。
2. 已停用且已标记为测试的加盟商，无论是否产生客资、派发、退回或积分业务，均允许永久清理。
3. 测试主体提供的客资即使已派给正式加盟商，也清理该测试来源业务链，但保留正式加盟商主体。
4. 测试主体只是接收方时，清理测试派发及下游记录，保留正式来源客资及正式来源公司。
5. 原成员账号不物理删除，而是停用、解除公司归属和微信身份；审计记录始终保留。
6. 历史正式主体转为测试主体前，超级管理员必须查看影响预览、输入完整公司名和固定确认短语，并使用最新范围令牌。
7. 加盟商详情弹窗应随桌面和移动视口自适应，不出现横向或嵌套可见滚动条，内容仍可完整滚动到达。

## 二、修改前后对比

| 范围 | 修改前 | 修改后 |
|---|---|---|
| 测试主体删除 | 只允许无跨公司、无外部积分关联的独立测试数据；有业务或派发时会被阻止 | 已停用测试主体可清理完整业务链，不以是否产生业务或派发作为阻断条件 |
| 正式数据保护 | 遇到跨公司关联直接拒绝，无法满足测试数据清理 | 根据来源和接收方边界保留正式主体与正式原始客资，仅删除测试链 |
| 历史主体标记 | 只输入公司名和原因即可把已停用主体标为测试 | 先返回客资、派发、退回、积分、证据和跨公司影响预览，再校验固定短语与最新 scope token |
| 积分处理 | 外部积分关联直接阻断 | 删除属于测试业务链的流水，按剩余不可变流水重算正式账户 `balance_after` 和余额 |
| 去重恢复 | 删除匹配记录后可能遗留错误重复状态，OVERRIDDEN 客资可能继续处于可派发状态 | 重新计算受影响客资；仍有正式重复时重新阻断，无重复时恢复到来源对应的可用状态 |
| 并发删除 | purge 与领取、退回终审、核验提交、奖励结算存在反向锁序等待风险 | PostgreSQL 业务锁统一使用 `NOWAIT`，冲突立即返回可重试 409，释放后重新执行即可 |
| 证据文件 | 删除数据库证据后缺少可靠的对象存储清理边界 | 同一数据库事务写入持久清理任务，提交后由调度器幂等删除；失败持续退避重试 |
| 存储目标保护 | 同名 Bucket 在不同 Endpoint 下可能被误认为同一目标 | 清理任务固定 backend、Endpoint、Region 和 Bucket；目标变化时拒绝删除 |
| 迁移回退 | 降级可能直接丢失尚未处理的对象键 | `0014` 在存在非 `DELETED` 任务时主动拒绝降级 |
| 加盟商详情 | 固定最大高度和内部 overflow 可能产生横向或嵌套滚动条 | 使用单一流式详情画布；背景锁定，外层自然滚动但隐藏滚动条，表格和长文本自动换行 |

## 三、独立评审发现与闭环

首轮独立审查提出 4 个 HIGH、2 个 MEDIUM，架构审查提出 2 个 BLOCK，最终均闭环：

- 修复 `OVERRIDDEN` 客资在另一正式重复仍存在时未重新进入 `DUPLICATE` 的问题。
- purge 对 PostgreSQL 锁冲突改为 `NOWAIT` + `COMPANY_PURGE_BUSY_RETRY` 409，并补领取、奖励、退回、核验四类真实未提交锁测试。
- S3 清理目标从“backend + bucket”补齐为“backend + endpoint + region + bucket”。
- migration `0014` 降级前检查未完成清理任务，避免丢失唯一对象键。
- 对象存储清理取消 `DEAD` 截断，失败保持 `FAILED` 并持续封顶退避重试。
- 正式历史主体误标风险增加 purge preview、固定短语和基于全部资源 ID 的最新范围令牌。
- 加盟商详情改为 overlay 单一滚动面，隐藏可见滚动条但不裁剪内容；打开弹窗时锁定背景页面滚动。

最终复审结果：代码审查 `APPROVE`，CRITICAL/HIGH/MEDIUM/LOW 均为 0；架构复审 `CLEAR`，没有合并阻断项。

## 六、性能与安全复核

- 清理只由 `*` 权限的超级管理员入口执行；普通运营仍只能停用或启用主体。
- 清理范围按批量 SQL 收集并锁定，没有逐条远程调用；对象存储 I/O 已移出业务事务。
- PostgreSQL 清理锁使用 `NOWAIT`，避免与领取、退回和奖励业务长时间互相等待。
- 对象存储 worker 使用有界批次；PostgreSQL 使用 `SKIP LOCKED` 支持多 worker 安全领取。
- 清理正式积分账户时一次锁定账户和相关流水，按时间与 ID 稳定顺序重算，避免遗留错误余额。
- 响应式弹窗没有新增前端依赖；只复用现有布局和现代浏览器已在项目中使用的 `:has()` 选择器。
