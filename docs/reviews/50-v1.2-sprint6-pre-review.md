# V1.2 Sprint 6 T30–T33 预评审记录

## 评审范围

- T30：历史手机号指纹回填、历史状态严格映射、数据对账；
- T31：全量回归、PostgreSQL 16 迁移门禁、配置和安全测试；
- T32：桌面管理后台和移动 H5 的 Chromium 交互/视觉证据；
- T33：生产预检、显式迁移、部署、UAT、Go/No-Go、回滚、备份恢复和灰度 Runbook。

## 预评审重点

1. 回填必须有界、幂等、可断点续跑且不得记录明文手机号；
2. 正式生产必须使用独立 `PHONE_FINGERPRINT_SECRET`；
3. 未知历史状态不得在迁移中静默映射到关闭/过期；
4. SQLite 迁移门禁之外必须增加 PostgreSQL 真实升级夹具；
5. 生产 API 启动不得隐式执行数据库迁移；
6. 浏览器门禁必须检查页面可见错误、console error 和 pageerror；
7. 积分、返分、奖励和有效派发单必须在上线前自动对账；
8. 代码完成与真实微信、UAT、恢复和灰度完成必须明确分离。

## 初始风险

- UUID 游标要求迁移期间冻结写入；Runbook 已将写入冻结设为强制前提；
- 历史解密密钥错误会造成指纹回填失败；脚本以非零退出阻断；
- 生产飞书可能不是首发必选；配置改为 `FEISHU_ENABLED` 显式控制；
- 旧 `RETURN_WINDOW_HOURS=48` 仍供 V1.0.1 接口兼容，V1.2 不读取该值；生产模板已移除；
- 真实浏览器 CI 不能替代 iOS/Android 微信和业务 UAT，已列为现场 Go/No-Go。

## 自动评审修复

- 修复 AWS S3 默认 endpoint 被错误强制配置；自定义 endpoint 才要求有效 HTTPS；
- 修复迁移 Runbook 在 V1.0.1 结构上提前运行 V1.2 脚本，新增无 PII 的 V1.0.1 基线工具；
- 修复 `FEISHU_ENABLED` 仅校验不阻断运行，读取、分页、令牌、同步和回写均增加运行时门禁；
- 强化预检输出对 `DATABASE_URL` 及嵌入口令的脱敏；
- 浏览器冒烟即使单场景失败也会保留 JSON、日志和已生成截图。
