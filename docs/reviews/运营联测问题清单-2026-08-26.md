# 运营联测问题清单（待五角色联测汇总后统一整改）

## 使用边界

本清单仅记录已在运营工作台联测中确认的问题和整改方向；在超级管理员、电销、加盟商负责人、加盟商员工完成联测并统一确认前，不直接修改业务代码或上线。

## 已记录问题

### 1. 客资所在地与城市选择

- 平台新建和加盟商新建客资的所在地应从全国省／市／区县中选择，不应受当前加盟商服务范围或本地预置城市限制。
- 客资字段统一使用“所在地”；“服务区域”仅用于加盟商覆盖能力，两个概念不得混用。
- 整改方式：复用全国地区树，表单按省、市、区县选择；需要覆盖全市时明确展示“全市／不限区县”。

### 2. 预算口径

- 页面输入、标签、范围提示均使用“万元”，不再显示“元”。
- 整改方式：允许小数万元输入，前端在提交和展示边界换算，底层金额继续按元保存；校验下限不得大于上限。

### 3. 人工派发接收公司

- 点击“选择接收公司”必须有弹窗、加载态、空态和失败提示，不能无反馈。
- 候选公司优先展示服务区域与客资所在地匹配、状态正常且满足派发条件的加盟商；支持按公司名称搜索其他公司。
- 跨区域公司应保留可见的规则说明。未形成明确的例外派发制度前，建议显示但不可直接派发，并记录审计。

### 4. 加盟商资料维护

- 管理端应支持更正加盟商资料；已有业务记录的公司不宜物理删除，应采用编辑、停用或归档，并留存审计记录。
- 联测时需确认：哪些字段允许运营改、哪些字段只允许超级管理员改，以及停用后在历史客资中的展示规则。

### 5. 操作日志与追溯

- 日志列表应以业务语言展示“谁、何时、对哪条客资／公司、完成了什么事项、结果是否成功”。
- 日志详情可进入，展示关联对象、前后状态、备注或附件、失败原因及不可变更的操作编号。
- 操作编号应支持复制和查询，不应被直接编辑；如需纠正，新增一条关联的更正操作而非改写历史。

### 6. 左下角账号中心与顶部操作

- 左下角账号入口必须可点击，包含个人资料、密码与安全、通知设置、帮助与退出等与账号有关的内容。
- 右上角仅保留刷新、设置、退出；不再放用户头像和账号信息。
- 左上角品牌统一显示“合家美宅统一工作台”，不显示版本号“1.2”。

### 7. 本地敏感配置存放（上线前安全项）

- 已发现项目目录的密钥资料中含有明文第三方服务配置；本清单不记录具体值，也不在联测中展示。
- 整改方式：确认该文件是否被版本控制或共享；如存在外泄可能，轮换对应密钥，将运行值迁移至服务器环境变量或专用密钥管理，并确保本地密钥目录不进入代码包和远程仓库。

## 后续联测范围

| 角色 | 本轮重点验证 |
| --- | --- |
| 超级管理员 | 账号与加盟商管理、充值权限、审计查看、运营同等的账号开停能力 |
| 运营管理员 | 已完成首轮；后续回归新建、审核、派发、异常处理和日志 |
| 电销人员 | 仅接收运营派发、电话核实、提交结论与退回资料 |
| 加盟商负责人 | 本公司客资提交、领取、内部员工分配、退回与公司资料可见范围 |
| 加盟商员工 | 自行提交、接收负责人分配、跟进与资料补充，且不能越权查看公司内部明细 |
