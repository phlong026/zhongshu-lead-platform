# 43 - V1.2 Sprint 1 客资供给前端评审

- 分支：`feature/v1.2-sprint1-lead-supply-ui`
- 目标分支：`release/v1.2.0`
- 评审范围：T05 平台录入后台、T11 供应商 H5、供应商初审队列补充接口
- 结论：通过，须以 PR 全量 CI 为最终合并门禁

## 1. 实现范围

### 平台管理后台

- 新增独立工作台 `v12-leads.html`，并按权限从现有后台侧栏进入。
- 平台客资列表、状态筛选、草稿创建、编辑、提交和详情。
- 城市/区县标准地区联动，提交授权确认和预算校验。
- 提交后展示去重结论；正常客资直接进入 `READY_DISPATCH`。
- 供应商资料初审队列、详情、通过和驳回。

### 供应商 H5

- 新增独立页面 `supplier.html`，并按权限从现有 H5 顶栏/个人中心进入。
- `LEAD_SUPPLIER` 能力状态展示和申请。
- 本公司客资草稿保存、编辑、提交、列表筛选和详情。
- 展示平台初审状态、去重结论和驳回说明。
- 明确客户授权、手机号加密/HMAC 去重和奖励观察期规则。

### 后端补充

- 新增供应商资料初审列表和详情读取接口。
- 列表强制限定 `SUPPLIER_H5` 来源，支持状态、初审状态和分页。
- 继续沿用 `lead.supplier.review` 权限和手机号字段隔离。

## 2. 冻结业务规则复核

- [x] 页面文案明确正常客资不生成前置电销任务。
- [x] 平台手工客资提交成功后进入待人工派发池，不提供自动、随机或抢单入口。
- [x] 供应商客资先进入资料初审，不在 H5 侧自行放行。
- [x] 供应商未获得已批准且启用的 `LEAD_SUPPLIER` 能力时不能上传。
- [x] 供应商页面仅读取本公司客资，后台初审接口仅向有审核权限的账号开放。
- [x] 手机号展示遵循后端字段权限；普通运营审核列表只返回脱敏手机号。
- [x] 客户授权是正式提交的必填条件。
- [x] 页面未调用 `LEAD_VERIFY` 或 `/verification/tasks`。

## 3. 交互与可用性评审

- 后台采用桌面独立工作台，保留返回原管理后台的明确入口。
- H5 针对移动端采用单列卡片、底部 Sheet 详情和安全区适配。
- 城市变更时重新加载所属区县，避免提交跨城市区县。
- 草稿与正式提交分离，允许信息不完整时先保存。
- 驳回必须填写原因；供应商可在列表和详情查看平台说明。
- 重复/疑似重复、资料初审和客资主状态分别展示，避免混淆。

## 4. 安全评审

- 动态文本统一 HTML 转义，未将用户输入直接作为可执行脚本。
- 请求使用同源 HttpOnly Cookie，不在浏览器本地保存访问令牌。
- 独立页面不引用外部 CDN 或远程运行时资源。
- 权限入口只是前端可见性控制，所有写入和对象访问仍由后端校验。
- 页面不显示手机号指纹、加密值、哈希或密钥。

## 5. 自动化验证

- JavaScript 全仓 `node --check`。
- Python 编译、秘密扫描和补丁空白检查。
- 独立 HTML 静态引用存在性与无外部运行时依赖。
- 后台 API 合约包含平台录入、供应商初审和标准地区，不包含前置核验接口。
- H5 API 合约包含能力申请、上传、列表、详情、授权字段和奖励观察提示。
- 后端测试覆盖初审队列来源隔离、手机号脱敏和无权限账号拒绝。

## 6. 遗留边界

- 本批不实现待派发池、候选公司筛选、人工派发和领取原子事务；对应 Sprint 2 T14-T17。
- 本批只说明供应商奖励规则，不展示奖励账务状态；奖励状态机和结算属于 Sprint 4 T22-T25。
- 浏览器真实数据 UAT、Figma 对照和视觉回归属于 T32-T33，上线前必须完成。
