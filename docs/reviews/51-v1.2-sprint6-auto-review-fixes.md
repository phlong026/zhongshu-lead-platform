# 代码评审：V1.2 Sprint 6 自动评审问题整改

- 评审时间：2026-08-07T07:10:00+08:00
- 评审范围：Sprint 6 PR #35/#37 自动评审提出的迁移、账务、S3、飞书、Compose Preflight、数据库凭据、镜像版本、历史账务兼容与证据持久化问题
- 总体结论：全部已知 P1/P2 已整改并关闭线程，等待当前最新 head 最终复审与 Release CI

## 第一轮已关闭问题

### P1：V1.2 扫描早于结构升级

原迁移 Runbook 在 V1.0.1 表结构上运行依赖 `phone_fingerprint` 和迁移检查点的 V1.2 脚本。整改后：

`V1.0.1 无 PII 基线 → Alembic upgrade head → V1.2 dry-run → 回填 → 对账`。

生产 Runbook 明确禁止在升级前执行 V1.2 扫描。

### P2：AWS S3 默认 Endpoint 被错误强制

生产配置校验允许 AWS S3 的 `S3_ENDPOINT_URL` 留空并由 SDK 选择区域端点；显式自定义 Endpoint 时必须为有效 HTTPS URL。

### P2：FEISHU_ENABLED 未形成运行时门禁

`FeishuClient`、同步路由、读取、分页、Token、导入和回写路径均执行运行时门禁。关闭时返回 503 且不会发起飞书网络请求，诊断接口仍可读取 enabled/configured 状态。

## 第二轮已关闭问题

### P1：Docker 生产 Preflight 误用宿主机 SQLite

标准 `.env` 仅包含 `POSTGRES_*`。整改后：

- 配置校验可由 `POSTGRES_*` 推导 Compose 内部 PostgreSQL URL；
- `preflight_v12.py --compose-database` 将 Alembic revision 和 V1.2 对账放到生产 Compose 网络执行；
- 未显式提供可达 `DATABASE_URL` 且未传 `--compose-database` 时直接失败，禁止回退 SQLite；
- 数据库 URL 和口令进入 Preflight 报告前全部脱敏。

### P2：run --rm 导致对账证据丢失

所有生产 reconciliation 报告改为通过标准输出写入宿主机 `dist/`，并通过 `python -m json.tool` 校验；Deployment、Migration Runbook、Go/No-Go 和生产检查表均将宿主机证据列为强制项。

## 第三轮已关闭问题

### P1：奖励/返分流水只检查存在，不检查业务语义

`reconcile_v12()` 已改为逐条验证：

- 已结算/已冲正奖励原流水的 supplier company、`REWARD`、`V12_SUPPLIER_REWARD`、reward ID 和 reward points；
- 冲正流水的 company、`REVERSAL`、`V12_SUPPLIER_REWARD_REVERSAL`、reward ID、负向金额以及 related original ledger；
- 已批准退回返分流水的 company、`RETURN`、受控 refund business type、return ID、返分金额，以及其关联的原 `CLAIM` 流水。

新增语义异常错误码并作为 `NO-GO`。回归测试专门构造“账户总额仍然平衡，但奖励流水指向错误业务”的场景，确认对账会失败。

### P2：迁移前 reconciliation 非零退出被 `|| true` 吞掉

Runbook 现在先保存 JSON、捕获 `reconcile_status=$?`、恢复 `set -e`、校验 JSON，最后在状态非零时原样退出。因此既保留失败证据，也不会把未知状态、积分/流水异常当作可继续回填。

### P2：宿主机数据库 URL 编码与 Compose 实际运行不一致

`docker-compose.yml` 不再直接插值拼接原始 `DATABASE_URL`，只向 API/Scheduler 传 `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB`。两个入口统一 source `docker/prepare-env.sh`，用 `urllib.parse.quote(..., safe='')` 构造 SQLAlchemy URL。宿主机校验使用相同编码规则。

测试覆盖空格、`@`、`/`、`#` 等保留字符；生产校验同时阻止重新引入原始 Compose URL 拼接。

### P2：APP_IMAGE 仅通过 `1.2.` 子串判断版本

最终生产镜像门禁改为：

- image reference 必须有显式 tag；
- tag 必须与 `APP_VERSION` 完全一致；
- 最终 `--compose-database` Preflight 必须存在 `@sha256:` digest；
- 本机实际拉取镜像必须可 `docker image inspect`；
- OCI `org.opencontainers.image.version` 必须与 `APP_VERSION` 完全一致。

环境模板和部署 Runbook 统一使用 `repo:APP_VERSION@sha256:digest`。

## 第四轮已关闭问题

### P1：V1.0.x 合法 `RETURN_REQUEST` 返分流水被 V1.2 语义对账误判

历史 `return_service.review_return()` 使用 `business_type="RETURN_REQUEST"`，V1.2 新终审使用 `V12_RETURN_REFUND`。最终 reconciliation 现在明确白名单两种受控历史语义：

- `RETURN_REQUEST`：V1.0.x 历史已批准退回；
- `V12_RETURN_REFUND`：V1.2 退回终审。

白名单仅放宽 business type，company、`RETURN` ledger type、return business ID、refund delta、related original CLAIM，以及 CLAIM 的 company/assignment/delta 仍严格一致。新增 `test_v12_reconciliation_legacy.py` 证明合法历史数据不会误触发 NO-GO。
