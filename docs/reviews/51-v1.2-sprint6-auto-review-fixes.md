# 代码评审：V1.2 Sprint 6 自动评审问题整改

- 评审时间：2026-08-06T22:20:00Z
- 评审范围：Sprint 6 PR #35/#37 自动评审提出的迁移、S3、飞书、Compose Preflight 与证据持久化问题
- 总体结论：通过

## 已关闭问题

### P1：V1.2 扫描早于结构升级

原迁移 Runbook 在 V1.0.1 表结构上运行依赖 `phone_fingerprint` 和迁移检查点的 V1.2 脚本。整改后：

`V1.0.1 无 PII 基线 → Alembic upgrade head → V1.2 dry-run → 回填 → 对账`。

生产 Runbook 现明确禁止在升级前执行 V1.2 扫描。

### P2：AWS S3 默认 Endpoint 被错误强制

生产配置校验现在允许 AWS S3 的 `S3_ENDPOINT_URL` 留空并由 SDK 选择区域端点；显式自定义 Endpoint 时必须为有效 HTTPS URL。

### P2：FEISHU_ENABLED 未形成运行时门禁

`FeishuClient`、同步路由、读取、分页、Token、导入和回写路径均执行运行时 `ensure_enabled()`。关闭时返回 503 且不会发起飞书网络请求，诊断接口仍可读取 enabled/configured 状态。

### P1：Docker 生产 Preflight 误用宿主机 SQLite

标准 `.env` 仅包含 `POSTGRES_*`，数据库 URL 由 Compose 注入。整改后：

- 配置校验可由 `POSTGRES_*` 推导 Compose 内部 PostgreSQL URL；
- `preflight_v12.py --compose-database` 将 Alembic revision 和 V1.2 对账放到生产 Compose 网络执行；
- 未显式提供可达 `DATABASE_URL` 且未传 `--compose-database` 时直接失败，禁止回退 SQLite；
- 数据库 URL 和口令进入 Preflight 报告前全部脱敏。

### P2：run --rm 导致对账证据丢失

所有生产 reconciliation 报告改为通过标准输出写入宿主机 `dist/`，并通过 `python -m json.tool` 校验；Deployment、Migration Runbook、Go/No-Go 和生产检查表均将宿主机证据列为强制项。

## 主动补强

- Dockerfile 默认版本修正为 `1.2.0`；
- 生产 API 禁止隐式迁移，Alembic 必须在维护窗口单独执行；
- Preflight 敏感值递归覆盖数据库 URL/口令；
- 浏览器场景失败时仍写 JSON 报告并保留已有截图/日志；
- 发布包避免重复 `RELEASE_MANIFEST.json`；
- 临时 Sprint 6 重复 CI 工作流在正式 PR/Release 门禁建立后移除。

## 结论

上述自动评审问题均已有对应代码、测试或 Runbook 处置。最终生产开放仍取决于 Release CI、真实微信、目标 PostgreSQL/对象存储、恢复演练、UAT 和灰度 Go/No-Go。
