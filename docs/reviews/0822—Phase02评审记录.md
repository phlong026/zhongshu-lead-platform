## 4. 发现清单

### P2（应整改）

| # | 位置 | 问题 | 置信 | 来源 |
|---|---|---|---|---|
| P2-1 | `routers/auth.py:376-388` | **callback 把 5xx 级故障折叠成 302**：`except AppError` 一律 302，`WECHAT_OAUTH_UNAVAILABLE`/`WECHAT_OAUTH_FAILED`（502）、`WECHAT_NOT_CONFIGURED`（503）全部变成 `AUTH_FAILED`。微信宕机/密钥错误在网络监控里显示为正常 302，用户被指引「重新获取邀请」制造无效工单；该分支零日志零审计。修复：仅 4xx 类绑定错误走状态页，`status_code>=500` 保留 5xx 或先落结构化日志 | 9（三方确认） | Codex+红队+可维护性 |
| P2-2 | `rbac.py:24/:88` + `admin/app.js:46` | **权限错配**：公司页对 `company.read` 开放（OWNER、FINANCE 均持有），但「邀请」「邀请记录」按钮无条件渲染，而创建/列表/撤销 API 全部 `require_permissions("*")`——这两类角色点击必得 403。P1 新增了第二个实例（邀请记录）。修复：按 `can('*')`（或细分 `invite.read`/`invite.manage`）隐藏入口 | 8（主审已核验 RBAC） | Codex |
| P2-3 | `h5/index.html` / `admin/index.html` | **`?v=` 未随本批前端改动递增**（仍 `20260820-clarity`，`enhancements.js`/`safe-html.js` 仍无版本参数）：后台缓存旧脚本看不到邀请记录；H5 旧脚本不认识 `auth-error` 路由（后果链见 §2 I3 行）。修复：随发布递增全部受影响脚本版本参数 | 7（双确认） | Codex+P0-I3 |
| P2-4 | `routers/auth.py:364/:376` | **「不出现裸 JSON」契约有两个确定缺口**：① `code`/`state` 为必填 query 参数，缺参在进 `try` 之前就被 FastAPI 422 JSON 拒绝；② 并发同 openid 回调撞 `WechatIdentity.openid` 唯一约束（models.py:181）抛 `IntegrityError`，不在 `except AppError` 内，全局处理器回 409 JSON。修复：callback 适配层统一包住参数校验与 IntegrityError（后者映射 `AUTH_FAILED` 302 并回滚），并与 P0-I14 的幂等重读一并处理 | 8（双确认） | Codex+红队 |
| P2-5 | `routers/auth.py:387` | **失败路径零审计零日志**：`AUTH_WECHAT_BOUND_OTHER_COMPANY`（转发误绑，UI 明示的威胁模型）、`AUTH_OAUTH_STATE_INVALID`（篡改/重放）、`AUTH_BINDING_CONFIRM_REQUIRED`（伪造意图）等安全失败零痕迹；同文件 `/auth/login` 对失败是有审计的，行为不一致。修复：except 分支补 `write_audit`（如 `WECHAT_OAUTH_BIND_FAILED`，metadata 记 reason_code + request_id） | 8（双确认） | 红队+可维护性 |
