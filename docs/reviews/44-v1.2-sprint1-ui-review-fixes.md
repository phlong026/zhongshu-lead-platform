# 44 - V1.2 Sprint 1 合并后 UI 评审问题修复

- 来源 PR：`#29`
- 修复分支：`fix/v1.2-sprint1-ui-review`
- 目标分支：`release/v1.2.0`
- 结论：待 PR 全量 CI 验证后可合并

## 1. 评审问题与处置

### P1：重复供应商客资无处理入口

**问题**：供应商客资进入 `DUPLICATE` 后，原页面隐藏通过和驳回按钮，也没有去重覆盖入口，运营无法闭环处理。

**修复**：

- `DUPLICATE` 行显示“去重放行”和“驳回”。
- “去重放行”调用既有高风险接口 `/v1.2/admin/leads/{id}/dedup-override`，强制填写至少 5 个字符原因。
- 放行后供应商客资进入 `PENDING_REVIEW`，同时将 `review_status` 设置为 `PENDING`，必须继续执行资料初审，不能直接进入待派发池。
- 未拥有 `lead.dedup.override` 权限时不显示放行按钮。

### P2：供应商初审“全部”筛选失效

**问题**：空字符串被 `|| 'PENDING'` 强制改回待审核，无法查询混合状态。

**修复**：

- 将筛选条件持久化到 `state.supplierReviewStatus`。
- 初始值为 `PENDING`，用户选择“全部”后保留空字符串并从请求中省略 `review_status`。

### P2：非本人草稿显示编辑/提交按钮

**问题**：运营可以读取全部平台录入草稿，但后端只允许提交人或超级管理员修改；原页面对所有草稿显示写操作，产生可预见的 403。

**修复**：

- 仅当 `submitter_user_id === 当前用户 id` 或当前用户拥有 `*` 权限时显示编辑和提交按钮。
- 其他草稿仅保留详情查看。

### P2：供应商 H5 只能查看前 100 条

**问题**：列表固定请求第一页 100 条，超过上限的历史记录不可访问。

**修复**：

- 改为每页 20 条的服务端分页。
- 增加上一页、下一页、当前页/总页数和总条数显示。
- 状态切换后自动回到第一页；保存或提交后回到第一页刷新。

## 2. 业务与安全复核

- 去重放行不等于资料初审通过，放行后仍停留在资料初审阶段。
- 重复客资可直接驳回，不要求先放行。
- 放行原因继续进入去重覆盖记录和审计日志。
- 前端只隐藏无权执行的按钮，后端对象归属与权限校验保持不变。
- 分页继续由后端执行公司级数据隔离。

## 3. 自动化验证

新增测试覆盖：

- 供应商重复客资放行后 `status=PENDING_REVIEW` 且 `review_status=PENDING`。
- 管理后台存在去重覆盖入口、空筛选持久化和草稿所有权守卫。
- 供应商 H5 使用真实分页参数与上一页/下一页控制，不再固定第一页 100 条。

未发现新增 Critical 或 High 风险。
