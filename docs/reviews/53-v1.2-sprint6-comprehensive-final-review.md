## 4. 积分、退回与奖励账务

账务采用账户快照 + 不可变 `points_ledgers`。终评特别检查“流水存在但关联错业务”的风险。

最终 reconciliation 验证：

- 账户余额 = delta 汇总 = 最新 `balance_after`；
- 领取扣分流水公司、业务类型、assignment ID 和负向金额；
- APPROVED 退回返分流水公司、`RETURN` 类型、return ID、正向金额以及关联原领取流水；
- SETTLED/REVERSED 奖励原流水 supplier company、`REWARD`、reward ID、奖励金额；
- REVERSED 冲正流水 supplier company、`REVERSAL`、reward ID、负向金额和 related original ledger；
- 证据 object key、64 位 SHA-256 和文件大小。

任一语义错误均使 reconciliation 非零并阻断 Go/No-Go。

## 5. 并发与幂等

人工派发、领取、返分和奖励关键写路径均包含服务层锁/状态重检和数据库约束：

- 人工派发对 lead 加 `FOR UPDATE`，再次计算候选资格；
- `0003_v12_active_assignment_constraint` 在 PostgreSQL/SQLite 创建同一 lead 的有效 assignment 部分唯一索引；
- assignment idempotency key 唯一；
- 派发只计算可用积分并预留，不提前扣分；
- 领取锁 assignment，重新检查状态/过期，并通过 points account 行锁 + 公司/idempotency 唯一流水扣一次；
- return request 对 assignment 唯一，终审锁 return/assignment/reward，并使用返分幂等键；
- supplier reward 对 assignment 唯一，结算/冲正锁 reward 和 points account，并使用唯一账务幂等键；
- notification outbox `event_key` 唯一；
- 迁移写者在 PostgreSQL advisory lock 下串行。

正式 PostgreSQL CI 还必须验证迁移 DDL、约束和真实数据库行为；目标环境根据真实规模继续观察锁等待与 P95。

## 6. 权限、隐私与安全

确认：

- 所有权限由后端 RBAC 决策，不依赖前端菜单隐藏；
- 加盟商数据按 company/assignment 关系隔离；
- 手机号领取前脱敏、领取后按授权解锁；
- 财务/积分字段按 permission 独立输出；
- 审计快照递归脱敏 phone/mobile/auth/token/secret/cookie 等字段；
- 深链只是导航，不承担授权；
- production 禁止微信/飞书 mock、弱密钥、Wildcard CORS/Trusted Hosts、Demo seed 和自动建表；
- Preflight 对数据库 URL、密码、Token、Secret、Access Key 脱敏；
- 自定义 S3 endpoint 必须 HTTPS，AWS 默认 endpoint 可留空；
- `FEISHU_ENABLED=false` 时客户端和路由运行时 fail-closed，不发外部请求。
