# V1.2 数据迁移 Runbook

## 1. 迁移目标

- 从 V1.0.1 数据结构升级到 Alembic `head`；
- 为历史客资生成独立 HMAC-SHA256 手机号指纹；
- 保持历史业务状态只读，不批量改写历史事实；
- 对积分、派发、退回、奖励和证据元数据进行上线前对账。

## 2. 强制前置条件

- 生产写入已冻结；
- 最新 PostgreSQL 与对象存储备份已校验并异地保存；
- `FIELD_ENCRYPTION_KEY` 可解密历史手机号；
- `PHONE_FINGERPRINT_SECRET` 已独立生成、托管，且不会在迁移后更换；
- 同版本 PostgreSQL 全量预演已通过；
- 回滚负责人、停止条件和恢复命令已确认。

## 3. 预迁移基线

```bash
python -m alembic -c alembic.ini current
python scripts/reconcile_v12.py --allow-incomplete-backfill \
  --output dist/v12-reconciliation-before.json || true
python scripts/migrate_v12_data.py --dry-run \
  --batch-size 500 --max-batches 10000 --fail-on-row-error
```

只读扫描出现 `PHONE_DECRYPT_FAILED` 或 `PHONE_FORMAT_INVALID` 时不得进入正式回填，应先修复数据或形成有审批的排除清单。

## 4. Alembic 升级

```bash
python -m alembic -c alembic.ini upgrade head
python -m alembic -c alembic.ini current --check-heads
```

记录开始时间、结束时间、锁等待、数据库大小和错误输出。超过预演时长 150%、出现长时间阻塞或任一迁移异常时立即停止。

## 5. 手机号指纹回填

```bash
python scripts/migrate_v12_data.py \
  --batch-size 500 \
  --max-batches 10000 \
  --fail-on-row-error
```

实现特性：

- 按业务 ID 有界分页；
- 每批提交，支持断点续跑；
- 使用 `v12_migration_checkpoints` 保存游标、处理数和错误数；
- 已生成指纹的记录不会重复处理；
- 检查点只记录业务 ID 和错误码，不记录手机号；
- 失败行整改后通过 `--reset` 显式重新扫描。

`--reset` 不会删除已生成指纹，只重置检查点。生产使用前必须经数据负责人审批。

## 6. 历史状态只读映射

V1.0.1 状态通过 `state_machine_v12.py` 映射为 V1.2 展示状态，不直接批量改写原始状态。迁移与对账使用严格模式；未知状态不会被静默归入关闭或过期，而是触发 `NO-GO`。

重点映射：

- `QUALIFIED` → `READY_DISPATCH`；
- `ASSIGNED` → `DISPATCHED`；
- `RETURN_PENDING` → `FOLLOWING`；
- `RETURNED` → `READY_DISPATCH`；
- 退回 `PENDING` → `SUBMITTED`；
- 退回 `NEED_MORE` → `NEED_MORE_EVIDENCE`。

## 7. 迁移后对账

```bash
python scripts/reconcile_v12.py --output dist/v12-reconciliation-after.json
```

必须满足：

- 所有历史客资均有手机号指纹；
- 回填检查点为 `COMPLETED` 且错误数为 0；
- 无未知客资或退回状态；
- 同一客资最多一个有效派发单；
- 每家公司积分余额等于流水汇总和最新 `balance_after`；
- `SETTLED` 奖励均有关联流水；
- `REVERSED` 奖励均有关联反向流水；
- `APPROVED` 退回均有关联返分流水；
- 证据 `object_key`、SHA-256 和文件大小完整。

## 8. 抽样要求

至少抽查：

- 20 条历史手机号及 90/180/365 天去重结论；
- 所有存在余额的公司，或不少于 20 家公司积分账；
- 10 条领取、10 条退回、10 条奖励；
- 截图和录音各不少于 5 个对象；
- 所有迁移错误或告警记录。

抽样表中不得记录明文手机号，应使用业务 ID 和脱敏号码。

## 9. 停止与回滚条件

立即停止：

- 迁移脚本非零退出；
- 数据库锁等待超过预演阈值；
- 手机号解密或指纹失败；
- 积分、奖励或返分对账出现差异；
- 证据对象大量缺失；
- 未知历史状态无法确认；
- 数据库或磁盘容量异常。

数据库恢复参见 `V1.2_ROLLBACK.md`。禁止在没有确认可逆性的情况下直接执行 Alembic downgrade。
