# V1.2 Go / No-Go 门禁

## 1. 判定规则

- 所有“必须”项通过才可判定 `GO`；
- 任一项缺少可核验证据，视为未通过；
- 代码自动测试不能替代真实微信、真实对象存储、业务 UAT、恢复演练或灰度结果；
- 决策由产品、业务、财务、技术和发布经理共同签字。

## 3. 自动证据命令

标准 Docker 生产部署必须使用版本 tag + sha256 digest 的不可变镜像和 Compose 数据库模式：

```bash
mkdir -p dist
python scripts/verify_production.py \
  --env-file .env \
  --require-certificates \
  --require-image-digest \
  --require-image-inspect \
  --scan-subject scan-subject.json
python scripts/preflight_v12.py \
  --env-file .env \
  --require-certificates \
  --compose-database \
  --storage-canary \
  --scan-subject scan-subject.json \
  --output dist/v12-preflight.json
python -m json.tool dist/v12-preflight.json >/dev/null
```

必须同时满足：

- `APP_IMAGE` 显式 tag 与 `APP_VERSION` 完全一致；
- `APP_IMAGE` 带 `@sha256:`；
- 已拉取镜像的 OCI `org.opencontainers.image.version` 与 `APP_VERSION` 完全一致；
- 已拉取镜像的 Docker ImageID 与 Security Analysis 产出的 `scan-subject.json` 完全一致；
- Alembic revision 与 V1.2 reconciliation 在生产 Compose 网络的真实 PostgreSQL 执行；
- `.env` 没有显式可达 `DATABASE_URL` 且未传 `--compose-database` 时 Preflight 失败，禁止回退本地 SQLite；
- migration/reconciliation 失败状态不得被吞掉；
- reconciliation JSON 持久化在宿主机 `dist/`，不得仅保存在 `run --rm` 容器内；
- 奖励结算/冲正与退回返分流水除余额一致外，还必须与公司、业务 ID、类型、金额和关联原流水语义一致；
- `PYSEC-2026-3552` 的临时豁免必须仍处于有效窗口；正式全量上线当天重新检查 `cryptography` 官方稳定版本，一旦修复版可安装，先升级、完整回归并删除 `--ignore-vuln`，不得带已可修复豁免上线。

以下证据仍需人工附加：

- CI 与代码评审链接；
- 真实微信和飞书联调；
- 浏览器/设备报告；
- UAT 签字；
- 备份恢复演练；
- 监控告警截图；
- 法务与业务审批；
- 依赖临时风险接受复核记录。

## 4. 上线停止条件

上线窗口出现以下任一情况立即 `NO-GO` 或回滚：

- 版本、image tag、digest 或 OCI version 任一不一致；
- 数据库迁移失败或超过预演时长 150%；
- 指纹回填存在失败行；
- 积分余额或奖励/返分业务语义对账异常；
- Preflight 连接的不是生产 PostgreSQL/Compose 数据库；
- OAuth、领取、扣分、退回、结算任一核心链路失败；
- 手机号、Token、证据或财务字段越权；
- 5xx、数据库连接、磁盘或 Scheduler 告警达到红线；
- 上线前备份不可验证；
- `cryptography` 官方修复版已经正式可安装但 CI 仍保留 `PYSEC-2026-3552` 豁免；
- 代码出现任何 `pkcs7_decrypt_*` 调用而风险接受仍处于启用状态；
- 关键责任人不在线。
