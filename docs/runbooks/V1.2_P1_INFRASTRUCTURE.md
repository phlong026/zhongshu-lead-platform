# V1.2 P1 基础设施准备 Runbook（Issue #42）

> 目标：将 V1.2.0 灰度最低生产拓扑落地到真实云环境，覆盖 Issue #42 全部 P0 验收项。
> 原则：任何一项 P0 无可归档证据即 `NO-GO`；不得带病进入 P2。

## 1. 参考拓扑与最低规格

```text
Internet / WeChat
       ↓ HTTPS
      Nginx
       ↓
FastAPI API + H5 + Admin
       ↓
Scheduler
       ↓
PostgreSQL 16（仅容器内网/云内网）
       ↓
私有 COS/S3（加密 + 版本 + 生命周期 + 审计）
```

- 1 台 4C8G Linux 云服务器（建议腾讯云 CVM，Ubuntu 22.04/24.04）；
- 独立持久化数据盘（PostgreSQL 数据目录与本地备份缓存）；
- Docker + Docker Compose；
- 正式域名 + DNS + TLS（80 强制跳转 443）；
- 云安全组仅开放 22/80/443（按需 22）；
- dev / staging / production 的域名、数据库、Bucket、Secret 完全隔离；
- 主机、容器、数据库完成 NTP 校时。

## 4. 执行步骤

### 4.1 主机引导（云资源到位后执行）

```bash
# 将仓库源码放到服务器（例如 /opt/zhongshu-lead-platform），然后：
cd /opt/zhongshu-lead-platform
sudo DATA_DISK_DEV=/dev/vdb DATA_DISK_MOUNT=/data \
  sh scripts/bootstrap_production_host.sh
```

脚本幂等：安装 Docker/Compose、挂载数据盘、chrony NTP、ufw 22/80/443、目录布局。
仅在显式 `FORMAT_DATA_DISK=1` 时格式化数据盘。

### 4.2 PostgreSQL 16 内网化

- 生产 Compose 使用 `docker-compose.prod.yml` 叠加层：db 仅 `expose: 5432`，不发布宿主机端口；
- 确认 `docker ps` 的 db 容器没有 `0.0.0.0:5432->` 或公网 IP 映射；
- 数据目录：建议将 compose volume 指向数据盘（`--postgres-data-bind /data/postgres` 由 verify 工具校验）。

### 4.3 私有 COS/S3

- 创建私有读写 Bucket，不提供永久公网 URL；
- 开启服务端加密、版本控制、生命周期（备份保留与 `BACKUP_RETENTION_DAYS` 对齐）、访问审计；
- 使用最小权限子账号凭据，仅允许 `PutObject/GetObject/ListBucket` 等必要操作；
- 凭据只写入目标机 `.env` 或 Secret 托管，绝不进入 Git/Issue/PR。

### 4.4 域名 / DNS / TLS

- 正式域名 A 记录指向服务器公网 IP；
- 申请并放置证书：`infra/certs/fullchain.pem`、`infra/certs/privkey.pem`（不入 Git）；
- 校验 `curl -I http://<域名>` 返回 301 到 https，`curl -I https://<域名>` 证书有效。

### 4.5 安全组

- 云控制台安全组仅放行 22/80/443（如关闭 SSH 公网访问则仅 80/443）；
- 与主机 ufw 形成纵深防御；`verify_infrastructure.py` 会列出公网监听端口核对。

### 4.6 NTP

- bootstrap 已安装 chrony；`timedatectl set-ntp true`；
- 容器与宿主机时钟偏差由 `verify_infrastructure.py` 的 `clock_offset_seconds` 验证（≤2s）。

### 4.7 环境隔离

- dev / staging / production 使用不同域名、数据库名、Bucket、Secret；
- `verify_infrastructure.py --environment production` 会拒绝包含 staging/dev/local/example 标记的配置。

## 5. 基础设施验证与证据归档

```bash
python scripts/verify_infrastructure.py \
  --env-file .env \
  --environment production \
  --expected-public-ports 80,443 \
  --require-tls \
  --require-object-storage \
  --postgres-data-bind /data/postgres \
  --output production-evidence/<YYYY-MM-DD>-p1-infrastructure/infrastructure-evidence.json
python -m json.tool production-evidence/<YYYY-MM-DD>-p1-infrastructure/infrastructure-evidence.json >/dev/null
```

- 退出码 0 = 无 P0 错误；2 = 存在 P0 错误；
- 证据 JSON 只包含脱敏信息；任何 Secret 不得写入；
- 在 Issue #42 中记录：服务器规格、区域、公网 IP（可脱敏）、域名、PostgreSQL 版本、Bucket 名（可脱敏）、TLS 检查结果与网络策略，并附 evidence 文件路径。

## 6. 受阻/未提供外部资源时的处理

- 完成并提交所有本地可执行工作（本 runbook、bootstrap 脚本、verify 脚本、证据模板）；
- 在 Issue #42 明确列出最小阻塞输入（第 3 节清单），标注当前阶段为 `BLOCKED-PENDING-EXTERNAL`；
- **不进入 P2**，直到 #42 全部 P0 验收通过并关闭。

## 7. NO-GO 规则

任一情况立即 `NO-GO`，禁止进入下一阶段：

- PostgreSQL 5432 暴露公网；
- PostgreSQL 数据目录不在持久化盘；
- 对象存储缺失加密/版本/生命周期/审计或存在公网读；
- TLS 缺失/过期/无 80→443；
- 安全组或监听端口超出放行清单；
- dev/staging/production 任一资源未隔离；
- 主机/容器/数据库 NTP 未同步或时钟偏差超限；
- 任何 Secret 出现在 Git、Issue、PR 或终端回显。
