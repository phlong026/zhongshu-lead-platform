# V1.2 工作日历初始化与维护手册

## 1. 目标与边界

工作日历是申诉截止和加盟商奖励观察截止的共享基础数据。本模块只维护日期是否计入工作日，不修改业务场景参数、微信配置、微信 App Secret 或其他密钥。

本轮不接入外部节假日 API，不自动下载或发布法定节假日。生产日历数据仍需经办人依据已批准的官方日历复核后导入。

## 2. 规则口径

- 业务日期固定按中国时区 `Asia/Shanghai` 计算。
- 未显式配置时，周一至周五默认是工作日，周六和周日默认是休息日。
- 法定节假日需显式设为休息日；周末调休需显式设为工作日。显式配置覆盖默认规则。
- 领取当天不计入“后续 3 个工作日”，从下一自然日开始累计，并保留领取时刻在中国时区的时分秒。
- 申诉截止和奖励观察截止调用同一工作日历服务，并在领取时同时固化到派发订单。
- 修改日历只影响保存后新领取或历史缺失字段补算；已固化的历史截止时间不回算。

## 3. 角色与权限

| 角色 | 查看 | 单日维护 | 批量导入 |
| --- | --- | --- | --- |
| `SUPER_ADMIN` | 允许 | 允许 | 允许 |
| `OWNER` | `calendar.read` | `calendar.manage` | `calendar.import` |
| `OPERATION` | `calendar.read` | 不允许 | 不允许 |
| 其他内部角色及加盟商 | 不允许 | 不允许 | 不允许 |

`calendar.manage` 和 `calendar.import` 是敏感权限。生产环境必须先按 [V1.2_RBAC_SYNC.md](./V1.2_RBAC_SYNC.md) 完成只读预览、人工复核和显式应用。

接口契约：

| 方法 | 路径 | 权限 | 返回口径 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/admin/v1.2/calendar-days?start=...&end=...` | `calendar.read` | 返回范围内每一天的有效结果，包含 `is_override`、来源、变更人和时间 |
| `PUT` | `/api/v1/admin/v1.2/calendar-days/{day}` | `calendar.manage` | 返回 `created`、`changed` 和 `FUTURE_CALCULATIONS_ONLY` 影响口径 |
| `POST` | `/api/v1/admin/v1.2/calendar-days/import` | `calendar.import` | 返回新增、更新、无变化数量和实际受影响日期范围 |

## 4. 管理端操作

### 4.1 查看月历

1. 使用有 `calendar.read` 权限的平台内部账号登录。
2. 进入“质量与系统 → 工作日历”。
3. 选择月份；页面展示该月每天的后端有效结果，并区分“系统默认”和“显式覆盖”。
4. 点击日期查看状态、来源、版本、变更人、变更时间和影响范围。

### 4.2 单日维护

1. 使用 `SUPER_ADMIN` 或 `OWNER`，点击“单日设定”或日期详情中的“编辑当天”。
2. 设置工作日/休息日并填写节日或调休说明。
3. 来源只能是 `MANUAL`、`OFFICIAL` 或 `IMPORT`；法定节假日和调休建议使用 `OFFICIAL`。
4. 版本必须是正整数；官方口径修订时应递增版本。
5. 相同数据重复保存会返回“无变化”，不更新 `updated_at`，也不重复写审计。

### 4.3 批量导入

页面支持简单 CSV、制表符文本和 JSON。单次最多 1000 天，同一批不允许重复日期。

CSV 示例：

```text
日期,是否工作日,节日或说明,来源,版本
2026-10-01,休息日,国庆节,OFFICIAL,1
2026-10-10,工作日,国庆调休工作日,OFFICIAL,1
```

JSON 示例：

```json
{"days":[{"day":"2026-10-01","is_workday":false,"holiday_name":"国庆节","source":"OFFICIAL","version":1}]}
```

导入前界面会显示数量和日期范围进行二次确认。导入后返回“新增/更新/无变化”数量。完全相同的批次重复执行时，数据、更新时间和审计均保持不变。

## 5. 生产初始化顺序

1. 完成数据库迁移，确认 `calendar_days` 表存在。
2. 完成 RBAC 差异预览和显式应用，确认 `OWNER` 有读/改/导入权限、`OPERATION` 只有读权限。
3. 由业务负责人准备本年和下一年的已批准官方节假日/调休清单。
4. 使用有 `calendar.import` 权限的账号导入，并记录导入人、数量、起止日期和来源版本。
5. 重复导入同一文件，结果应全部为“无变化”，作为幂等性证据。
6. 抽查至少一个法定节假日、一个周末调休和一个默认工作日。
7. 用 `OPERATION` 复核可查看但无维护/导入按钮；用无 `calendar.read` 的账号复核接口返回 403。
8. 检查 `V12_CALENDAR_DAY_UPSERT` 或 `V12_CALENDAR_IMPORT` 审计。

第 3-8 步属于生产/UAT 验收。本地自动化、健康路由或浏览器 smoke 通过，不等于实际官方节假日已在生产导入并验收。

## 6. 审计与更正

- 单日有效变更写入 `V12_CALENDAR_DAY_UPSERT`。
- 批量有效变更写入 `V12_CALENDAR_IMPORT`，记录新增、更新、无变化数量和受影响日期范围。
- 配置错误时不要删除历史记录；使用正确值和递增版本再次覆盖，并记录更正依据。
- 恢复上一版时，从审计和上一份已批准导入文件取回正确值，复核后再次导入。

## 7. 自动化验收

```bash
pytest -q apps/api/tests/test_v12_calendar_admin_http.py apps/api/tests/test_v12_workday_calendar.py apps/api/tests/test_v12_calendar_schema.py apps/api/tests/test_workday_calendar_admin_contract.py apps/api/tests/test_v12_browser_smoke_contract.py
```

本地 PostgreSQL + Chromium 证据位于 `dist/browser-smoke-cal01/browser-smoke-report.json`。它只证明当前候选代码在隔离空库完成管理员维护、幂等导入和运营只读权限 smoke，不代表外部系统或生产 UAT 已通过。

浏览器脚本默认只读。只有对一次性隔离数据库执行验收时，才允许增加 `--calendar-write-smoke`；禁止将该参数指向共享开发、UAT 或生产数据库。
