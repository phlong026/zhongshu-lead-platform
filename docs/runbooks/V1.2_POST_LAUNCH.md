# V1.2 灰度发布与上线复盘

## 1. 灰度范围

首批选择 3–5 家满足以下条件的加盟商：

- 已完成账号、服务区域、供给/接收能力和积分初始化；
- 老板及操作人员已参加培训；
- 有明确问题反馈联系人；
- 能覆盖供应客资、接收客资、退回和奖励等主要场景；
- 不与高风险历史数据整改同时进行。

禁止首日直接向全部加盟商开放。

## 2. 分批策略

| 阶段 | 范围 | 最短观察 | 扩大条件 |
|---|---:|---:|---|
| 内部冒烟 | 平台测试账号 | 2小时 | 核心链路和对账通过 |
| 灰度1 | 3–5家公司 | 24–72小时 | 无P0/P1、告警稳定、对账为0 |
| 灰度2 | 20–30家公司 | 3天 | 指标和支持能力稳定 |
| 分批扩大 | 每批不超过当前规模50% | 2–3天 | 上一批通过复核 |
| 全量 | 全部批准公司 | 持续 | 多方签字 |

## 3. 每日监控

技术指标：

- 请求量、P50/P95/P99；
- 4xx/5xx；
- API、Scheduler、Nginx 容器健康；
- PostgreSQL 连接、CPU、磁盘、慢查询；
- Outbox PENDING/FAILED/DEAD；
- 到期奖励积压和最近 Scheduler 成功周期；
- 对象上传失败和授权访问失败；
- 备份执行和证书有效期。

业务指标：

- 供应提交和初审通过率；
- 待派发、待领取、领取成功量；
- 领取扣分与积分余额差异；
- 退回原因、补证、通过和驳回；
- 奖励观察、冻结、结算、冲正；
- 微信通知成功率和深链到达；
- 用户反馈和人工支持工单。

## 4. 红线

出现以下任一情况停止扩量：

- P0 或未解决 P1；
- 积分、返分、奖励对账差异不为0；
- 重复领取、重复派发或重复结算；
- 手机号、证据或财务字段越权；
- OAuth、通知或对象存储大面积失败；
- 5xx 或性能持续超过批准阈值；
- Scheduler、Outbox 或备份失去可观测性；
- 客服支持无法在承诺时限内响应。

## 5. 24小时复核

- 检查全部红线；
- 对账所有灰度公司的积分和奖励；
- 抽查至少 10 条客资全链路；
- 核对通知和审计；
- 汇总用户操作问题；
- 决定继续、暂停或回滚。

## 6. 72小时复核

- 对比容量和性能预估；
- 分析退回率、初审效率和领取效率；
- 复核工作日截止和奖励定时任务；
- 确认无隐性数据积压；
- 更新培训、SOP 和常见问题；
- 多方签字决定是否扩大。

## 7. 7天复盘

复盘至少包括：

- 目标与实际结果；
- 缺陷、故障和用户反馈；
- 性能、容量和成本；
- 数据迁移与对账；
- 权限和隐私事件；
- 运维响应和恢复能力；
- 业务流程、规则和培训问题；
- 下一补丁版本的范围、责任人和时间。
