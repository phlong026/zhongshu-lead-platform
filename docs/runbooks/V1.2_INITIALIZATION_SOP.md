# 合家美宅客资平台 V1.2 全角色初始化与操作 SOP

## 1. 使用范围与当前边界

本手册面向第一次接触系统的管理员、加盟商负责人、客资供应方和内部电销人员，说明如何从空库完成身份初始化，并按当前 V1.2 页面完成日常操作。

本产品由微信公众号内 H5、PC 管理后台和内部电销 H5 组成，业务上常称“客制派发小程序”，但当前实现不是原生微信小程序。当前入口如下：

| 使用端 | 入口 | 主要使用人 |
| --- | --- | --- |
| PC 管理后台 | `/admin/` | 平台内部账号 |
| V1.2 运营台 | `/admin/v12-operations.html` | 运营、管理员、审核人员 |
| 账号与角色 | `/admin/index.html#/users` | `SUPER_ADMIN` |
| 加盟商公司 | `/admin/index.html#/companies` | `SUPER_ADMIN` |
| 人工充值 | `/admin/index.html#/recharge` | `FINANCE`、`SUPER_ADMIN` |
| 工作日历 | `/admin/index.html#/calendar` | `OWNER`、`OPERATION`、`SUPER_ADMIN` |
| 加盟商工作台 | `/h5/v12-workbench.html` | `FRANCHISE_OWNER` |
| 供应客资页面 | `/h5/supplier.html` | 已获 `LEAD_SUPPLIER` 能力的加盟商负责人 |
| 内部电销台 | `/call/` | `TELESALES`；`SUPER_ADMIN` 仅作管理或应急 |

### 1.1 本轮冻结项

- 涉及微信明文、微信 AppSecret、网页授权域名和真实 OAuth 的操作当前暂缓，任何人不得执行、抄录或在本手册补入真实值。
- 涉及业务场景配置参数、积分档位、价格规则、派发策略、工作日历正式数据及部署默认值的调整当前暂缓，不得执行新增或改值。本手册只允许使用已经批准、已经生效的数据。
- 生产配置、迁移、备份和回滚只按 `docs/runbooks/DEPLOYMENT.md`、`docs/runbooks/V1.2_MIGRATION_RUNBOOK.md` 与 `docs/runbooks/V1.2_ROLLBACK.md` 执行；本手册不复制生产凭据或环境参数。
- 本地自动化通过只证明候选代码可运行，不等于真实微信、真实生产数据、灾备、移动端和业务 UAT 的真实环境验收通过。

### 1.2 操作纪律

1. 先确认当前 Git 提交、数据库备份和 Alembic revision，再做初始化。
2. 账号、公司、权限、积分、区域和审核只走现有脚本、API 或 UI；禁止手工改生产数据库。
3. 失败时停止在当前步骤，保留错误码和脱敏截图，不跨步骤“口头放行”。
4. 验收截图不得包含真实手机号、微信标识、邀请 token、密码、密钥或生产个人数据。

## 2. 身份与权限模型

V1.2 使用代码固定的角色权限矩阵。管理员只能为内部账号分配完整角色，不能为个人任意勾选权限点；权限基线见 `apps/api/src/services/rbac.py`，同步手册见 `docs/runbooks/V1.2_RBAC_SYNC.md`。

| 身份 | 典型职责 | 关键边界 |
| --- | --- | --- |
| `SUPER_ADMIN` | 首装、内部账号、公司和邀请、全局应急管理 | 拥有 `*`；系统必须至少保留一个启用中的超级管理员 |
| `OWNER` | 业务和财务看板、审计、报表、工作日历 | 不能创建内部账号、公司或邀请 |
| `LEAD_ENTRY` | 平台手工录入和维护客资 | 不负责派发、积分和终审 |
| `OPERATION` | 客资初审、去重、人工派发、加盟商能力/区域审核 | 工作日历只读；不能代替财务充值 |
| `TELESALES` | 退回后的 `RETURN_VERIFY` 事实核验 | 只能领取和处理本人任务；手机号按任务状态解锁 |
| `FINANCE` | 积分充值、冲正、奖励管理和财务报表 | 本轮只使用已有已发布档位，不调整积分配置参数 |
| `RETURN_REVIEWER` | 查看证据并终审退回 | 电销事实核验完成前不能终审 |
| `FRANCHISE_OWNER` | 加盟商工作台、领取、跟进、退回、供应客资 | 不在内部账号页分配；必须由公司邀请和绑定链路建立 |

加盟商的“供应商”不是新角色。`FRANCHISE_OWNER` 的公司在 `LEAD_SUPPLIER` 能力获批后可以供应客资，在 `LEAD_RECEIVER` 能力和服务区域获批后可以接收派发；同一公司可以申请其中一项或两项能力。

## 3. 管理员首装与初始化 SOP

### 3.1 执行前提

- 测试环境依赖已按 `README.md` 安装，数据库连接由受控环境预先提供。
- 生产环境已按 `docs/runbooks/PRODUCTION_CHECKLIST_V1.2.md` 完成维护窗口、写入冻结和备份；未满足时直接判定 `NO-GO`。
- 本轮不处理冻结的微信凭据和配置参数。遇到相关步骤，只登记“待解除暂停”，不得临时填值绕过。

### 3.2 首装步骤

| 步骤 | 入口 | 所需角色 | 操作步骤 | 成功结果 | 常见错误 | 回退方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 1. 数据库迁移 | 终端；生产按迁移 Runbook | 运维数据库权限 | 测试环境执行 `python -m alembic -c alembic.ini upgrade head`，再执行 `python -m alembic -c alembic.ini current --check-heads`。生产只引用 `docs/runbooks/V1.2_MIGRATION_RUNBOOK.md` 的 Compose 流程 | 数据库到当前 Alembic head；对账没有未知状态、重复有效派发单或积分差异 | 旧结构提前执行 V1.2 数据处理、迁移阻塞、对账异常 | 立即停止；按备份和 `docs/runbooks/V1.2_ROLLBACK.md` 恢复，不手工修表 |
| 2. 预览并同步固定 RBAC | 终端 | 数据库运行权限 | 先执行 `python scripts/sync_rbac.py` 预览；复核 `removed` 后执行 `python scripts/sync_rbac.py --apply --source release_v1.2.1`；最后再次执行预览 | 最终 `result.changed=false`；有变化时出现 `SYSTEM_RBAC_SYNC` 审计；`SUPER_ADMIN` 保留 `*` | 预览仍为 `changed=true`；出现无法解释的权限回收 | 回到上一版已批准代码矩阵，按“预览 → 复核 → 应用 → 再预览”恢复，禁止直接改映射表 |
| 3. 创建首位超级管理员 | 终端 | 无后台账号；仅限已迁移数据库 | 执行 `python scripts/bootstrap_superadmin.py --username <内部登录账号> --display-name <显示名称>`，按提示隐藏输入并确认密码 | 返回 `created`；重复执行返回 `already_exists`；审计包含 `SYSTEM_SUPERADMIN_BOOTSTRAP`，不记录密码 | 未到最新迁移、数据库非空但没有有效超级管理员、两次密码不一致、密码策略不满足 | 已创建但命名错误时，先登录新建另一名 `SUPER_ADMIN`，再停用旧账号；不得删库或直接改密码哈希 |
| 4. 首次登录 | `/admin/` | `SUPER_ADMIN` | 使用刚创建的内部账号登录；确认进入 `/admin/v12-operations.html`，再打开系统设置入口 | 页面显示当前角色允许的菜单；刷新后仍保持登录 | 账号停用、密码错误、会话失效、反复跳回登录页 | 先重新登录；仍失败时检查账号状态和服务日志，不创建重复账号绕过 |
| 5. 创建内部账号 | `/admin/index.html#/users` | `SUPER_ADMIN` | 按岗位逐一填写姓名和登录账号，只选择 `OWNER`、`LEAD_ENTRY`、`OPERATION`、`TELESALES`、`FINANCE`、`RETURN_REVIEWER` 或额外 `SUPER_ADMIN`；系统自动生成初始密码，创建后立即复制并通过受控渠道交给本人，需要轮换时由超级管理员在本页重置 | 成功弹窗显示一次性初始密码且可复制；列表出现账号及角色；改角色、重置密码、启停均产生审计并使旧会话失效 | `INTERNAL_IDENTITY_INVALID`、`INTERNAL_ROLE_REQUIRED`、`INTERNAL_ROLE_INVALID`、`LAST_SUPER_ADMIN_REQUIRED` | 未复制就关闭弹窗时，在同页立即重置密码；不得把 `FRANCHISE_OWNER` 填入内部账号 |
| 6. 创建加盟商公司 | `/admin/index.html#/companies` | `SUPER_ADMIN` | 填写名称、负责人、联系方式、主要城市和服务区县；系统创建积分账户，并将接单资格与服务地区以待审核状态提交 | 公司列表出现新公司；积分账户就绪；接单资格和服务地区均未激活、显示待审核 | 无 `*` 权限、`REGION_NOT_FOUND`、`SERVICE_AREA_HIERARCHY_INVALID` | 资料错误时在审核前修正；停止合作时停用公司，不删除数据库记录 |
| 7. 生成加盟商邀请 | `/admin/index.html#/companies` | `SUPER_ADMIN` | 在目标公司行点击“邀请”，核对公司后生成一次性邀请；真实微信授权与绑定当前仅登记待验收，不触碰冻结凭据 | 返回邀请标识、有效期和一次性链接；邀请对象与公司一致 | `AUTH_INVITE_INVALID`、链接过期/撤销、跨公司绑定触发 `AUTH_WECHAT_BOUND_OTHER_COMPANY` | 发错对象立即撤销并重新生成；不复用旧 token，只通过受控的一对一渠道发送，不进入群聊、截图或验收记录 |
| 8. 审核能力与服务区域 | `/admin/v12-operations.html?view=companies` | `OPERATION` 或 `SUPER_ADMIN` | 审核后台建档代录或加盟商后续提交的 `LEAD_SUPPLIER`、`LEAD_RECEIVER` 和服务区域申请，逐项通过、驳回或停用 | 获批能力为 active；获批区域进入接收候选条件；审核原因可追溯 | `CAPABILITY_REQUEST_NOT_FOUND`、`SERVICE_AREA_NOT_FOUND`、驳回原因为空 | 加盟商重新申请后再审；能力可重新通过或停用；禁止直接改区域表 |
| 9. 人工积分充值 | `/admin/index.html#/recharge` | `FINANCE` 或 `SUPER_ADMIN` | 只选择已有、已发布且当前有效的积分档位；录入线下付款参考，二次确认款项后提交 | 提示积分入账并生成不可变流水、通知与审计 | `POINTS_RECHARGE_CONFIRM_REQUIRED`、`POINTS_EXTERNAL_REFERENCE_EXISTS`、`POINTS_PACKAGE_INACTIVE`、`POINTS_CASH_AMOUNT_MISMATCH` | 错账通过冲正生成反向流水；不得编辑或删除历史流水，也不得为完成首装临时新建档位 |
| 10. 工作日历 | `/admin/index.html#/calendar` | `OWNER` 或 `SUPER_ADMIN` 维护；`OPERATION` 只读 | 本轮配置参数冻结，只验证页面和权限，不导入或修改正式日期；解除暂停后按 `docs/runbooks/V1.2_WORKDAY_CALENDAR.md` 导入已批准日历 | 当前阶段记录“入口/权限已验证，正式数据待验收”；解除暂停后重复导入应无变化 | `INVALID_DATE_RANGE`、`DUPLICATE_CALENDAR_DAY`、无维护或导入权限 | 当前不得执行改值；恢复后用已批准文件覆盖更正并保留审计，不删除历史 |
| 11. 首装验收 | 本节及第 6 节 | `SUPER_ADMIN` + 各岗位代表 | 逐角色登录，只验证其应见入口和应拒绝入口；记录提交、环境、结果和证据等级 | 固定角色、公司、审核、积分和三端入口均有脱敏证据；冻结项保持未执行 | 用超级管理员代替所有角色验收、把本地测试写成生产通过 | 删除错误结论，按真实角色重新验证；真实微信、生产数据和灾备继续保留为 Gate |

### 3.3 内部账号建议分配

| 岗位 | 建议角色 | 初始化后第一项验收 |
| --- | --- | --- |
| 系统负责人 | `SUPER_ADMIN` | 可进入账号、公司和全部系统入口 |
| 业务负责人 | `OWNER` | 可看业务/财务/审计/报表；不可新建账号和公司 |
| 客资录入 | `LEAD_ENTRY` | 可录入和维护平台客资；不可派发 |
| 运营 | `OPERATION` | 可初审、去重、人工派发、审核加盟商能力和区域 |
| 电销 | `TELESALES` | 只进入 `/call/` 并处理本人 `RETURN_VERIFY` 任务 |
| 财务 | `FINANCE` | 可用已有档位充值、冲正和处理奖励 |
| 退回终审 | `RETURN_REVIEWER` | 可查看退回证据并在电销提交后终审 |

### 3.4 如何客制化派发与设置权限

当前允许的“客制化”是按组织和岗位使用既有能力，而不是在页面自由创造流程：

1. `SUPER_ADMIN` 在账号页按岗位分配固定角色。
2. `SUPER_ADMIN` 建公司并生成绑定邀请；加盟商身份不能从内部账号页直接分配。
3. 加盟商申请供给/接收能力和服务区域，`OPERATION` 审核后决定其可供应或可接收的范围。
4. `OPERATION` 在当前 V1.2 规则下人工选择合格加盟商派发，系统继续执行公司状态、`LEAD_RECEIVER`、服务区域、积分余额和“供需不得同公司”等约束。
5. 不支持任意勾选个人权限，也不支持自动、随机、轮询、权重或抢单派发。需要新增角色、权限点或派发策略时，应先变更需求、权限矩阵、负向测试和审计设计，不能在生产数据库临时加权。
6. 当前冻结期间不得调整配置参数、价格/积分规则、派发场景值或正式工作日历；只使用已经审批的数据。

## 4. 加盟商与供应商 SOP

### 4.1 身份建立和资料审核

| 步骤 | 入口 | 所需角色 | 操作步骤 | 成功结果 | 常见错误 | 回退方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 1. 接收邀请 | 管理员生成的一次性链接 | 待绑定加盟商负责人 | 先核对邀请展示的公司；真实微信授权当前暂缓，不继续到需要微信凭据的现场步骤 | 邀请公司正确，状态有效；真实绑定记为待 `GATE-03` | `AUTH_INVITE_INVALID`、邀请过期/撤销 | 联系管理员撤销旧邀请并重新生成；不要转发或复用链接 |
| 2. 公司绑定 | `/h5/v12-workbench.html` | 绑定成功后的 `FRANCHISE_OWNER` | 解除微信暂停并完成真实授权后，确认工作台显示本公司；本轮只验证既有测试合同，不操作真实微信配置 | 当前账号只看到所属公司的信息和积分 | `COMPANY_REQUIRED`、`COMPANY_INACTIVE`、`AUTH_WECHAT_BOUND_OTHER_COMPANY` | 由管理员核对公司状态和绑定关系；禁止用另一个公司邀请覆盖既有绑定 |
| 3. 申请能力 | `/h5/v12-workbench.html` 的“加盟商设置” | `FRANCHISE_OWNER` + `company.profile.manage` | 按真实业务选择 `LEAD_SUPPLIER`、`LEAD_RECEIVER` 或两者，填写申请说明后提交 | 能力显示待审核；审核后 active 状态准确 | `CAPABILITY_INVALID`、公司未绑定或停用 | 修正资料后重新申请；被驳回不影响历史审核记录 |
| 4. 申请服务区域 | `/h5/v12-workbench.html` 的“加盟商设置” | `FRANCHISE_OWNER` + `company.profile.manage` | 选择主要城市及其下属区县后提交；区域必须与已批准业务范围一致 | 区域进入待审核；通过后参与接收候选过滤 | `SERVICE_AREA_REQUIRED`、`PRIMARY_CITY_REQUIRED`、`PRIMARY_CITY_INVALID`、`SERVICE_AREA_HIERARCHY_INVALID`、`REGION_NOT_FOUND` | 修正主要城市/区县后重提；移除申请获批前原有效区域继续生效 |
| 5. 管理员审核 | `/admin/v12-operations.html?view=companies` | `OPERATION` 或 `SUPER_ADMIN` | 管理员逐项核验能力、区域和原因后审批 | `LEAD_SUPPLIER`/`LEAD_RECEIVER` 与服务区域状态可追溯 | 申请不存在、驳回原因缺失 | 退回加盟商重提；禁止口头同意后手工改库 |

### 4.2 供应、领取、跟进和退回

| 步骤 | 入口 | 所需角色 | 操作步骤 | 成功结果 | 常见错误 | 回退方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 1. 供应客资 | `/h5/supplier.html` | `FRANCHISE_OWNER` 且公司 `LEAD_SUPPLIER` 已生效 | 填写客资资料，先保存草稿，复核后提交平台初审 | 提交后进入 `PENDING_REVIEW`；运营审核通过后进入 `READY_DISPATCH` | 未获供给能力、资料缺失、重复提交 | 保留草稿修正后再提交；已提交内容由运营按审核流程处理，不重复创建 |
| 2. 查看并领取派发 | `/h5/v12-workbench.html` 的“我的客资” | `FRANCHISE_OWNER` 且公司 `LEAD_RECEIVER` 和区域已生效 | 打开待领取派发，核对摘要与扣分，点击领取；只处理本公司订单 | 订单进入已领取状态，积分流水和领取时间可追溯 | `ASSIGNMENT_NOT_FOUND`、`ASSIGNMENT_NOT_CLAIMABLE`、`POINTS_INSUFFICIENT` | 刷新确认状态；积分不足由财务按已发布档位充值；禁止重复点击或改流水 |
| 3. 提交跟进 | `/h5/v12-workbench.html` 的“我的客资”详情 | `FRANCHISE_OWNER` + `followup.own.manage` | 选择跟进结果、填写备注并提交；提交后查看历史和最新状态 | 跟进历史刷新，当前状态与提交结果一致 | `FOLLOWUP_NOT_ALLOWED`、订单不属于本公司、重复点击 | 刷新详情后按当前状态重试；不可跟进时联系运营核对派发状态 |
| 4. 申请退回 | `/h5/v12-workbench.html` 的订单详情 | `FRANCHISE_OWNER` + `return.own.manage` | 在当前批准的期限内填写原因，并至少提供聊天截图或电话录音之一后提交 | 退回进入审核链；需要事实核验时生成 `RETURN_VERIFY` 任务 | `RETURN_NOT_CLAIMED`、`RETURN_NOT_ALLOWED`、`RETURN_WINDOW_EXPIRED`、`RETURN_EVIDENCE_REQUIRED` | 缺证据时补齐后再提交；超期或状态不允许时保留记录并联系平台，不伪造证据 |
| 5. 查看结果 | `/h5/v12-workbench.html` 的“退回/奖励/消息” | `FRANCHISE_OWNER` | 查看退回结论、积分变化、供应奖励和通知；对异常记录业务 ID | 状态、积分流水、奖励和消息相互可追溯 | 页面状态未刷新、消息延迟、金额不一致 | 先刷新；仍异常时停止重复操作，向运营/财务提供脱敏业务 ID |

## 5. 内部电销 SOP

V1.2 电销只处理退回后的事实核验，不做正常客资的前置外呼。任务状态依次为 `PENDING`、`ASSIGNED`、`IN_PROGRESS`、`SUBMITTED`；列表没有独立的 `PENDING` 筛选项，未分配任务在“全部”和工作台统计中查看。

| 步骤 | 入口 | 所需角色 | 操作步骤 | 成功结果 | 常见错误 | 回退方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 1. 登录与查看任务 | `/call/` | `TELESALES`；`SUPER_ADMIN` 仅管理/应急 | 登录后打开“核验任务”，按全部、待处理、核验中或已提交查看；列表和未领取详情只显示脱敏号码 | 只看到本人已分配任务或可领取的未分配任务 | 当前账号不是电销角色、未登录、`FORBIDDEN` | 重新登录正确账号；用底部导航“核验任务 / 工作台”返回，不依赖详情顶部返回按钮 |
| 2. 领取任务 | `/call/` 任务详情 | `TELESALES` + `verification.task.claim` | 确认是 `RETURN_VERIFY` 后点击领取 | 任务变为 `IN_PROGRESS` 并归属当前电销；此时详情才可显示明文手机号 | `RETURN_VERIFY_TASK_NOT_FOUND`、`RETURN_VERIFY_TASK_NOT_CLAIMABLE`、任务已被他人领取 | 刷新列表；已被领取时停止操作，不要求管理员改归属绕过 |
| 3. 拨号核验 | `/call/` 任务详情 | 当前领取人 + `lead.phone.dial` | 在 `IN_PROGRESS` 状态点击拨号，按退回事实进行核验并记录事实 | 只有当前领取人获得拨号目标；操作进入审计 | `RETURN_VERIFY_TASK_NOT_OWNED`、`RETURN_NOT_VERIFYING`、设备不支持拨号 | 刷新状态；设备问题使用经批准的工作设备，禁止复制手机号到非受控渠道 |
| 4. 提交结论 | `/call/` 任务详情 | 当前领取人 + `verification.submit` | 填写 `contact_result`、`conclusion` 和不少于 2 个字的 `note` 后提交 | 任务变为 `SUBMITTED`，手机号重新脱敏，终审人员可继续审核 | 备注过短、状态已变化、`RETURN_VERIFY_TASK_NOT_OWNED`、`RETURN_NOT_VERIFYING` | 保留已核事实，刷新后确认；已提交时不得重复提交 |
| 5. 异常处理 | `/call/` | `TELESALES` / `SUPER_ADMIN` | 记录任务 ID、当前状态、错误码和脱敏截图；旧版写入口不得恢复 | 问题可由运营按任务状态定位；不泄露手机号 | `LEGACY_WRITE_DISABLED`、旧字段导致 422、查看他人任务返回 403 | 返回 V1.2 任务列表重试；不得开启旧写路径作为临时回退 |

### 6.1 放行口径

- `代码完成`：脚本、页面、权限和文档已在受控提交中。
- `自动化通过`：单元、集成、PostgreSQL、浏览器合同或 smoke 已通过。
- `真实环境验收`：真实微信、目标 PostgreSQL/对象存储、移动端、生产数据、备份恢复、全角色 UAT 和灰度已现场签字。
- 前两项不能替代第三项。任何暂缓 Gate、P0/P1 缺陷或不明积分/权限差异存在时，均不得判定生产 Go。

## 7. 常见问题总表

| 问题 | 判断 | 处理 |
| --- | --- | --- |
| 登录后看不到某菜单 | 先核对固定角色，不先假定页面故障 | 由 `SUPER_ADMIN` 在账号页修正完整角色；不要直接加个人权限点 |
| 加盟商看不到供应入口 | 公司可能没有生效的 `LEAD_SUPPLIER` | 在工作台提交能力申请，由运营审核 |
| 公司不能成为派发候选 | 检查启用状态、`LEAD_RECEIVER`、已批准区域和积分余额 | 逐项按业务流程补齐，不绕过候选过滤 |
| 邀请失效或绑错公司 | 查看 `AUTH_INVITE_INVALID` / `AUTH_WECHAT_BOUND_OTHER_COMPANY` | 撤销旧邀请并核对绑定；真实微信处理继续遵守暂停边界 |
| 最后一个超级管理员不能停用 | `LAST_SUPER_ADMIN_REQUIRED` 是安全保护 | 先创建并验证另一名 `SUPER_ADMIN`，再停用旧账号 |
| 充值重复或金额不匹配 | 检查线下参考号、幂等键和已发布档位 | 不重复提交；错账走冲正，不改历史流水 |
| 电销看不到明文手机号 | 只有当前领取人且任务为 `IN_PROGRESS` 才可见 | 先领取并刷新；`SUBMITTED` 后按设计重新脱敏 |
| 页面健康但真实微信不可用 | 健康路由不代表 OAuth 验收 | 保持 Gate 未通过；待暂停解除后按真实设备和平台配置验收 |
