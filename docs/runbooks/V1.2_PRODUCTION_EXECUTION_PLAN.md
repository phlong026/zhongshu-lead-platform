## 3. P1：基础设施准备

### 3.1 灰度阶段最低拓扑

现阶段优先满足“先稳定跑通真实业务”，建议采用以下最小生产拓扑：

```text
Internet / WeChat
       ↓ HTTPS
      Nginx
       ↓
FastAPI API + H5 + Admin
       ↓
Scheduler
       ↓
PostgreSQL 16
       ↓
Private COS/S3
```

灰度最低资源建议：

- 1 台 4C8G Linux 云服务器；
- 独立数据盘用于 PostgreSQL 数据目录和本地备份缓存；
- PostgreSQL 16 仅通过容器内部网络或云内网访问，不开放公网 5432；
- 私有 COS Bucket 保存截图、录音等证据；
- 域名 + HTTPS；
- Docker + Docker Compose；
- Nginx / API / Scheduler / PostgreSQL 同机部署仅用于首批灰度和低并发阶段。

### 3.2 全量前升级条件

出现任一情况，必须评估将 PostgreSQL 迁移至独立托管数据库或独立数据库主机：

- 加盟商范围明显扩大；
- 数据量和附件量持续增长；
- CPU / 内存 / 磁盘 IO 持续超过安全阈值；
- 需要独立高可用、自动备份或跨可用区恢复；
- 应用扩容到多实例。

### 3.3 基础设施 P0 验收

- [ ] 正式域名已解析；
- [ ] TLS 证书有效，80 强制跳转 443；
- [ ] Nginx 安全响应头、限流和 25MB 上传限制已生效；
- [ ] PostgreSQL 16 不暴露公网；
- [ ] PostgreSQL 数据目录使用持久化卷/数据盘；
- [ ] COS/S3 Bucket 为私有读写，不提供永久公网 URL；
- [ ] COS/S3 开启加密、版本控制、生命周期和访问审计；
- [ ] dev / staging / production 数据库、Bucket、域名和 Secret 完全隔离；
- [ ] 服务器、容器、数据库完成 NTP 校时；
- [ ] 主机防火墙 / 安全组仅开放必要端口。

## 4. P2：正式配置与 Secret

生产配置从 `.env.docker.example` 生成真实 `.env`，**真实 `.env`、密钥、证书、数据库密码不得提交 Git**。

### 4.1 应用与镜像

必须配置：

```text
APP_ENV=production
APP_VERSION=1.2.0
APP_IMAGE=<registry>:1.2.0@sha256:<reviewed-digest>
APP_BASE_URL=https://<正式域名>
LOG_JSON=true
AUTO_CREATE_SCHEMA=false
SEED_DEMO=false
```

要求：

- `APP_IMAGE` 必须使用版本 tag + sha256 digest；
- 镜像 OCI `org.opencontainers.image.version` 必须与 `APP_VERSION` 一致；
- 禁止使用 `latest` 作为生产发布依据。

### 4.2 安全密钥

必须生成并独立托管：

```text
JWT_SECRET
FIELD_ENCRYPTION_KEY
PHONE_HASH_SECRET
PHONE_FINGERPRINT_SECRET
POSTGRES_PASSWORD
```

强制规则：

- `PHONE_HASH_SECRET != PHONE_FINGERPRINT_SECRET`；
- 不得使用示例值、默认值或相同密码；
- 密钥由专门的 Secret 管理或受控密码库保存；
- 应至少有两名有权限的负责人知道恢复流程，但不在群聊、文档和 Git 中明文传播。

### 4.3 微信

```text
WECHAT_APP_ID
WECHAT_APP_SECRET
WECHAT_OAUTH_SCOPE=snsapi_base
WECHAT_OAUTH_REDIRECT_URI=https://<正式域名>/api/v1/auth/wechat/callback
WECHAT_DEV_MOCK=false
```

### 4.4 对象存储

```text
OBJECT_STORAGE_BACKEND=s3
S3_ENDPOINT_URL
S3_ACCESS_KEY_ID
S3_SECRET_ACCESS_KEY
S3_BUCKET
S3_REGION
```

腾讯 COS 可通过当前 S3 兼容接口接入，但必须使用私有 Bucket 和最小权限凭据。

### 4.5 飞书

如果 P0 暂不启用飞书同步：

```text
FEISHU_ENABLED=false
FEISHU_DEV_MOCK=false
```

如果启用，则必须完整配置 App / Token / Table / Field Mapping，并完成增量同步、幂等与失败回写验证。

### 4.6 配置自动验证

```bash
python scripts/validate_production_env.py --env-file .env
python scripts/verify_production.py \
  --env-file .env \
  --require-certificates \
  --require-image-digest \
  --require-image-inspect \
  --scan-subject scan-subject.json
```

任一命令返回非 0：`NO-GO`。

## 5. P3：微信服务号与 H5 联调

### 5.1 微信后台必须配置

- 企业主体认证服务号；
- 网页授权域名；

### 5.2 菜单原则

H5 页面部署在自己的服务器，不上传到服务号后台。服务号菜单仅配置对应 H5 URL。

P0 菜单应以真实业务入口为主，不为了“菜单数量”强行拆页面。建议首批至少提供：

- 客资工作台；
- 客户 / 任务入口；
- 我的 / 个人中心。

最终菜单以真实角色业务流为准。

### 5.3 微信 P0 验收

必须在真实 iOS / Android 微信环境验证：

1. OAuth 登录；
2. 用户与公司绑定；
3. 登录态 Cookie / Session；
4. 派发通知；
5. 领取通知；
6. 退回申诉 / 审核结果通知；
7. 奖励通知；
8. 深链跳转；
9. 跨公司深链越权失败；
10. 失效深链不得泄露客资摘要。

## 6. P4：生产数据迁移预演

不得直接拿生产唯一副本做第一次 V1.0.1 → V1.2 迁移。

### 6.1 预演流程

```text
生产旧库备份
   ↓
恢复到隔离演练环境
   ↓
生成 V1.0.1 baseline
   ↓
Alembic upgrade V1.2
   ↓
手机号 fingerprint dry-run
   ↓
正式 backfill
   ↓
V1.2 reconciliation
   ↓
约束校验
   ↓
恢复 / 回滚演练
```

### 6.2 必须记录

- 数据库大小；
- 迁移开始 / 结束时间；
- 总耗时；
- 回填总行数；
- 错误行数；
- 锁等待；
- 磁盘增长；
- migration checkpoint 状态；
- reconciliation 结果；
- 恢复耗时。

### 6.3 强制 NO-GO

出现以下任一情况禁止上线：

- `COMPLETED_WITH_ERRORS`；
- 未知历史状态；
- 手机号指纹缺失；
- 重复有效派发；
- 积分余额 / 流水不一致；
- 奖励流水语义不一致；
- 退回返分流水语义不一致；
- PostgreSQL 必要唯一约束或部分唯一索引缺失；
- 对象存储证据 hash / object_key 不一致；
- 恢复演练失败。

## 9. P7：3–5 家加盟商灰度

### 9.1 试点选择

首批选择 3–5 家：

- 有真实客资量；
- 有明确负责人；

- 持续服务不可用；

## 11. 回滚触发条件

### 11.1 应用回滚

适用：代码 / 页面 / API 缺陷且数据库数据保持一致。

操作：将 `APP_IMAGE` 切换到上一已验证的 `tag@sha256:digest` 后重新启动。

### 11.2 业务冻结

以下情况优先冻结写入口，而不是继续尝试补数据：

- 积分异常；
- 重复领取 / 重复返分；
- 奖励重复结算；
- 越权；
- 客资数据错乱。

立即暂停：

- 领取；
- 返分；
- 奖励结算；
- 必要时暂停派发。

### 11.3 数据恢复

数据库迁移或数据损坏问题：优先恢复上线前备份，不得未经评审直接盲目 Alembic downgrade。

完整命令见 `V1.2_ROLLBACK.md` 和 `BACKUP_RESTORE.md`。

9. 产品、业务、财务、技术共同签字；
10. 生产证据包完整归档。
