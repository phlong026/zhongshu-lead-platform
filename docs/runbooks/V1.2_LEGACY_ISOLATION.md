# V1.2 生产 Legacy 隔离 Runbook

## 目标

V1.2 上线后，V1.0.1 数据可以继续查询和追溯，但不得通过旧业务 API 创建新的业务事实。所有新增客资、派发、领取、退回和后置核验必须走 V1.2 路径。

## 生产配置

生产环境必须同时满足：

```env
APP_ENV=production
LEGACY_WRITE_ENABLED=false
```

`validate_production_settings()` 会拒绝 `LEGACY_WRITE_ENABLED=true` 的生产配置。`docker-compose.prod.yml` 同时对 API 和 Scheduler 显式覆盖为 `false`，避免 `.env` 误配置重新打开历史写路径。

## 默认页面入口

- `/admin/` → `/admin/v12-operations.html`
- `/h5/` → `/h5/v12-workbench.html`

历史页面只用于追溯：

- `/admin/legacy` → `/admin/index.html`
- `/h5/legacy` → `/h5/index.html`

历史页面存在不代表历史 mutation API 在生产可用。

## 运行时写入门禁

production 且 `LEGACY_WRITE_ENABLED=false` 时，以下 Legacy 路径的 `POST` / `PUT` / `PATCH` / `DELETE` 请求统一返回：

```text
HTTP 410
code = LEGACY_WRITE_DISABLED
```

受保护前缀：

- `/api/v1/leads`
- `/api/v1/verification`
- `/api/v1/dispatch`
- `/api/v1/claims`
- `/api/v1/returns`

`GET` / `HEAD` / `OPTIONS` 不被该门禁阻断，仍由原 RBAC、公司归属和对象级权限控制。

V1.2 路径 `/api/v1/v1.2/...` 不在 Legacy 门禁范围内。

## 上线前验证

```bash
python scripts/validate_production_env.py --env-file .env
python scripts/verify_production.py --env-file .env --require-certificates --require-image-digest --require-image-inspect
```

并在目标环境验证：

1. `/admin/` 302 到 V1.2 运营台；
2. `/h5/` 302 到 V1.2 工作台；
3. Legacy GET 在有权限时仍可读取历史数据；
4. Legacy mutation 返回 410；
5. V1.2 录客、人工派发、领取、3 工作日退回和 `RETURN_VERIFY` 可正常写入；
6. 不再能创建新 `LEAD_VERIFY`、48 小时退回或截图+录音 AND 规则的新业务事实。

## 回滚边界

不得为了处理 V1.2 功能问题而在 production 临时设置 `LEGACY_WRITE_ENABLED=true`。若 V1.2 写路径出现阻断级故障，应冻结相关业务入口并按 `V1.2_ROLLBACK.md` 处理，而不是回退到旧业务规则继续写数据。
