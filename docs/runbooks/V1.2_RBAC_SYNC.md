# V1.2 固定 RBAC 精确同步手册

## 1. 目标与边界

`ROLE_PERMISSION_MATRIX` 是 V1.2 固定角色权限的唯一代码基线。同步只处理该矩阵中的固定角色：

- 补齐代码矩阵中存在、数据库映射中缺失的权限；
- 解绑数据库映射中存在、代码矩阵中已经移除的权限；
- 保留 `Permission` 记录，避免破坏历史审计或其他引用；
- 不修改矩阵外的自定义角色；
- 不提供任意勾选权限点的动态权限编辑器。

## 2. 生产前只读预览

默认命令只读，不提交事务：

```bash
python scripts/sync_rbac.py > dist/v12-rbac-preview.json
python -m json.tool dist/v12-rbac-preview.json >/dev/null
```

生产 Docker 部署必须在与 API 相同的 Compose 数据库网络内执行：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml \
  run --rm -T -e RUN_DB_MIGRATIONS=false api \
  python scripts/sync_rbac.py \
  > dist/v12-rbac-preview.json
```

预览 JSON 包含：

- `result.changed`：是否存在差异；
- `result.added_count`：将新增的角色权限映射数量；
- `result.removed_count`：将回收的角色权限映射数量；
- `result.roles[].added` / `result.roles[].removed`：每个固定角色的具体权限差异；
- `result.roles[].role_created`：该固定角色是否尚未初始化。

在执行应用前，技术负责人和业务负责人必须共同复核 `removed`。`SUPER_ADMIN` 必须保留 `*`；运营、电销、财务、退回审核和加盟商角色的关键权限必须与代码矩阵一致。任何无法解释的权限收缩均判定为 `NO-GO`。

生产 API 启动只执行同一份只读检查；只要 `changed=true` 就拒绝启动，并提示先完成预览和显式应用。生产启动不会代替人工复核，也不会自行回收权限。

## 3. 显式应用与审计

只有带 `--apply` 才会修改数据库：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml \
  run --rm -T -e RUN_DB_MIGRATIONS=false api \
  python scripts/sync_rbac.py --apply --source release_v1.2.0 \
  > dist/v12-rbac-apply.json
```

有实际变化时，数据库写入一条 `SYSTEM_RBAC_SYNC` 审计，保存执行来源以及逐角色新增、移除结果。重复执行在矩阵已经一致时返回 `changed=false`，不重复写审计。
命令结果只写 stdout，运行日志写 stderr，因此 stdout 可直接重定向为单一合法 JSON 文件。

全新空库若由超级管理员初始化脚本首次建立固定角色，也会在同一事务写入 `SYSTEM_RBAC_SYNC`，随后再写 `SYSTEM_SUPERADMIN_BOOTSTRAP`；因此首次初始化和已有库升级都有可追溯记录。

应用后再次只读预览：

```bash
docker compose --env-file .env -f docker-compose.yml -f docker-compose.prod.yml \
  run --rm -T -e RUN_DB_MIGRATIONS=false api \
  python scripts/sync_rbac.py \
  > dist/v12-rbac-after.json
```

`v12-rbac-after.json` 必须满足 `result.changed=false`。三个 JSON 文件均应持久化到宿主机并进入上线证据包。

## 4. 并发与回滚

PostgreSQL 应用同步时使用事务级 advisory lock，避免多个 API 实例或运维任务同时替换权限集合。同步只解绑 `RolePermission`，不删除 `Permission` 数据，因此回滚方式为：

1. 回退到上一版已批准代码矩阵；
2. 再次执行只读预览；
3. 复核差异后使用 `--apply` 恢复上一版固定角色映射；
4. 确认预览重新收敛为 `changed=false`。

不要直接在生产数据库手工补回映射，否则下一次生产启动会被差异门禁拒绝，显式同步仍会按代码矩阵收敛。

## 5. 自动化验收

```bash
pytest -q \
  apps/api/tests/test_rbac_exact_sync.py \
  apps/api/tests/test_sync_rbac_cli.py \
  apps/api/tests/test_admin_extended_pages_v10.py
```

验收必须证明：缺失权限被补齐、陈旧权限被收回、重复同步幂等、自定义角色和权限记录保留、预览不写库、显式应用结果进入审计。
