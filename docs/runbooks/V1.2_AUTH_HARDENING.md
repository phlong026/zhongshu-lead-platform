# V1.2 管理后台认证加固 Runbook

## 目标

本 Runbook 定义 V1.2 内部账号密码登录的生产安全边界。微信加盟商登录继续使用公众号 OAuth，不使用本节的内部账号锁定流程。

## 生产访问边界

1. `/admin` 优先通过企业 VPN、固定办公出口 IP 白名单、WAF/零信任网关或等效可信入口访问；
2. 不建议将管理后台无条件暴露给全公网；
3. Nginx 登录限流是纵深防御，不替代网络访问边界；
4. API 容器不直接暴露公网端口，外部请求统一经过 Nginx/TLS。

### 可信代理与真实客户端 IP

Nginx 登录限流使用 `$binary_remote_addr`。如果 Nginx 前面还有 WAF、负载均衡、VPN 网关或零信任代理，必须先把 `$remote_addr` 恢复为真实客户端 IP，否则所有用户会共享代理节点的限流桶。

生产变量：

```text
TRUSTED_PROXY_CIDR=127.0.0.1/32
```

默认只信任 loopback，不信任外部请求携带的 `X-Forwarded-For`。

如果存在外层可信代理：

1. 将 `TRUSTED_PROXY_CIDR` 设置为**实际代理出口 CIDR**；
2. 仅从该可信代理接收 `X-Forwarded-For`；
3. 不得配置为 `0.0.0.0/0`、`::/0` 或 `*`；
4. 如果有多个不连续代理网段，优先在最外层 WAF/网关同时实施登录限流，或维护受控的多条 `set_real_ip_from` 配置，不要扩大到全网段；
5. production preflight 会拒绝通配符/全网段可信代理配置。

## 登录保护

默认配置：

```text
LOGIN_MAX_FAILED_ATTEMPTS=5
LOGIN_FAILURE_WINDOW_MINUTES=15
LOGIN_LOCK_MINUTES=15
```

行为：

- 同一内部账号在失败窗口内累计 5 次失败后进入 15 分钟临时锁定；
- 锁定状态持久化在 `auth_login_state`，多 API 实例共享；
- PostgreSQL 使用 User 行锁串行化同账号认证状态更新；
- SQLite 开发/测试环境使用原子 upsert 累加失败次数，避免并发首次失败丢计数；
- 锁定期间即使密码正确也不能绕过；
- 锁定到期后下一次登录自动解除锁定并写审计；
- 不存在的用户名保持统一 `AUTH_LOGIN_FAILED` 响应，不返回账号存在性细节；
- Nginx 对 `/api/v1/auth/login` 使用独立 IP 级限流并以 HTTP 429 拒绝高频请求。

## 浏览器会话

- `/api/v1/auth/login` 成功后 JWT 只写入 `access_token` Cookie；
- Cookie 必须为 `HttpOnly`、production `Secure`、`SameSite=Lax`、`Path=/`；
- 登录 JSON 响应不得返回 raw JWT；
- 退出登录增加 `session_version`，已有 JWT 立即失效；
- 停用账号后，即使旧 JWT 尚未到期，`/auth/me` 和业务接口也必须拒绝。

## 平台内部账号生命周期

只有持有 `SUPER_ADMIN` 的启用账号能够进入管理后台“账号角色”页并调用 `/api/v1/users` 管理接口。固定可分配角色为：

- `SUPER_ADMIN`
- `OWNER`
- `LEAD_ENTRY`
- `OPERATION`
- `TELESALES`
- `FINANCE`
- `RETURN_REVIEWER`

管理员可以创建多角色内部账号、修改角色、停用、重新启用和重置密码。角色、状态或密码发生变化时，服务端递增该账号的 `session_version`，该账号已签发的 Cookie/Bearer 会话立即失效；重复提交相同角色或相同启停状态不重复递增版本，也不重复写审计。

内部账号必须满足：使用账号密码登录、`company_id` 为空、没有微信身份绑定且不包含 `FRANCHISE_OWNER`。加盟商负责人仍只能通过“创建公司 → 生成邀请 → 微信 OAuth 绑定”建立，不能从内部账号接口创建、改角色、启停或重置密码。

安全约束：

- 密码为 12–128 位，必须同时包含大小写字母、数字和符号，且不能包含登录账号；
- 平台始终保留至少一个启用中的 `SUPER_ADMIN`；最后一个超级管理员不能被停用或移除该角色；
- PostgreSQL 使用事务级 advisory lock 串行化超级管理员创建、降权和停用判断；
- 本模块只分配固定角色，不提供任意勾选权限点的动态权限编辑器。

管理 API：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/users` | 仅列出平台内部账号 |
| `POST` | `/api/v1/users` | 创建内部账号，使用 `role_codes` 多角色列表；旧单角色 `role_code` 暂保留兼容 |
| `PUT` | `/api/v1/users/{user_id}/roles` | 替换固定角色集合 |
| `POST` | `/api/v1/users/{user_id}/disable` | 停用并使旧会话失效 |
| `POST` | `/api/v1/users/{user_id}/enable` | 重新启用并使旧会话失效 |
| `POST` | `/api/v1/users/{user_id}/reset-password` | 管理员重置密码并使旧会话失效 |

## 审计

认证相关事件：

- `AUTH_LOGIN`：成功登录；
- `AUTH_LOGIN_FAILED`：密码错误；
- `AUTH_LOGIN_LOCKED`：达到失败阈值并锁定；
- `AUTH_LOGIN_BLOCKED`：锁定期或账号停用导致阻断；
- `AUTH_LOGIN_UNLOCKED`：锁定到期自动恢复；
- `AUTH_LOGOUT`：退出并使当前会话版本失效。

内部账号管理事件：

- `USER_CREATE`；
- `USER_ROLES_UPDATE`；
- `USER_DISABLE`；
- `USER_ENABLE`；
- `USER_PASSWORD_RESET`。

上述账号管理审计只记录角色、状态和会话版本变化，不记录密码、密码哈希或原始令牌。

审计允许记录：user_id、失败次数、锁定截止时间、request_id、来源 IP、User-Agent、reason code。

审计禁止记录：

- 密码；
- raw JWT / Cookie；
- Authorization header；
- Secret；
- 手机号明文。

## 账号被锁定时

正常处理：等待锁定窗口到期，并确认是否存在误输密码、共享账号或凭据泄露。

禁止：

- 修改代码临时绕过锁定；
- 降低 production 门禁后直接重启；
- 将账号密码发送到聊天、Issue、PR、日志；
- 因业务着急直接删除审计记录。

确需紧急数据库解锁时，应作为受控运维操作：

1. 记录工单/审批；
2. 确认用户身份；
3. 对 `auth_login_state` 进行最小字段修复；
4. 同时旋转密码/会话（如怀疑泄露）；
5. 保留数据库操作证据和事后审计说明。
