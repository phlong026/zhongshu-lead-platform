# V1.2 五角色工作台 P0 技术合同

状态：已确认，页面开发与上线前强制门槛
日期：2026-08-25
依据：`DESIGN.md`、`docs/plan/V1.2五角色统一工作台开发清单.md`、`docs/reviews/V1.2五角色统一工作台文档综合评估-2026-08-25.md`

## 1. 目的与实施原则

本文件把已确认的五角色业务规则转换为后端、路由、页面和测试可共同遵循的最小技术合同。它不是新增一套平行平台的设计。

- 先复用：既有 V1.2 派发/领取、退回核验、积分流水、奖励冻结与冲正、审计、Outbox 通知、全流程追溯接口优先保留。
- 只补缺口：只有角色边界、任务状态、数据归属或页面入口无法满足本合同的地方才新增字段、接口或页面。
- 不重写：不得以“统一”为名重新实现已经通过回归验证的扣积分、退款、奖励冲正、COS 证据、审计和通知投递。
- 先测试后迁移：每个行为变更先用回归测试锁定，再修改服务、路由和页面。
- 分阶段发布：结构迁移、数据迁移、权限收敛、页面退出各自独立提交和可回滚。

### 1.2 强制门槛

以下六项合同必须同时满足，才允许合并任何影响正式工作台的页面，或把本版本标记为可上线：

1. 后端接口、权限负例和状态转换符合对应合同；
2. 正式页面只展示当前角色的可执行工作，不以隐藏按钮代替接口鉴权；
3. 自动化回归、浏览器 smoke、迁移升级/回滚和安全检查均有通过证据；
4. 生产前置项（备份恢复、账号迁移 dry-run、COS、通知和真实 UAT）有独立记录。

任何一项缺失时，只能进行不改变业务状态的原型讨论；不得作为五角色页面交付或生产上线依据。

### 1.1 现有能力复用映射

|---|---|---|
| 运营派发、负责人领取、积分扣减 | `services/dispatch_v12.py`、`routers/v12_dispatch.py` | 员工内部协作归属、角色数据范围 |

## 2. 合同一：五角色、账号生命周期与数据范围

### 2.1 唯一业务角色

每个活跃账号恰好拥有一个业务角色：`SUPER_ADMIN`、`OPERATION`、`TELESALES`、`FRANCHISE_OWNER`、`FRANCHISE_EMPLOYEE`。旧 `OWNER`、`LEAD_ENTRY`、`FINANCE`、`RETURN_REVIEWER` 仅在迁移期间可读，不得作为新开户、登录落地页或新接口授权依据。

| 角色 | 核心权责 | 数据范围 | 明确禁止 |
|---|---|---|---|
| 超级管理员 | 全局治理、资金、审计；可开通/关闭加盟商负责人和员工账号 | 全局；客资总览可见当前加盟商跟进人，查看公司内部交接历史须填写理由 | 无理由查看敏感内部交接历史；删除资金/审计流水 |
| 运营管理员 | 加盟商日常开户、审核、初审、派发、电销派发/改派、异常与退回终审 | 平台业务全局；客资总览可见当前加盟商跟进人 | 查看员工之间的分配/回收历史；资金写入 |
| 电销人员 | 处理运营指派的前置核验或退回事实核验；提交事实结论 | 仅本人已派发且进行中的任务可看完整号码 | 自主领取、转派、派发、终审、退款、积分写入 |
| 加盟商负责人 | 本公司供资、领取、公司内部员工分配/回收、跟进、退回、人员申请 | 本公司；公司内部明细 | 审核自身供资、平台派发、资金写入 |
| 加盟商员工 | 直接供资、处理被分配客资、补证和退回 | 本人创建、本人被分配或要求补正的记录 | 查看公司总池、员工明细、积分、派发 |

### 2.2 加盟商账号操作

- 运营管理员和超级管理员均可创建、邀请、启用、停用、重置和绑定加盟商负责人/员工账号。
- 运营是日常操作责任人；超级管理员执行该类操作时，接口必须要求操作理由，并记录操作人、目标账号、公司、操作前后状态和审计事件。
- 负责人只能提交员工新增/停用申请、查看公司人员，不能直接授予角色、查看密码或停用账号。
- 停用账号时必须递增 `session_version`；有未完成员工任务时，先进入“待交接”或完成负责人转交，不能静默遗失。

### 2.3 电话与公司内部可见性

- 运营端显示号码脱敏值；完整号码仅向本人进行中的电销任务、拥有已领取客资的公司侧授权人员显示。
- 运营和超级管理员可在客资总览查看当前加盟商跟进人；明确分给员工时显示员工姓名，否则显示加盟商公司名称。
- 管理端不展示员工 A 向员工 B 分配/回收的历史事件，也不开放公司人员任务清单。
- 公司内部协作事件保留不可篡改审计；超级管理员按理由查询时产生单独高风险审计。

### 2.4 必要测试

- 五个角色逐一验证菜单、接口、数据范围与越权拒绝。
- 多角色创建/更新、旧角色新开户、无理由超级管理员内部明细查询均必须失败。
- 运营与超级管理员均可管理加盟商账号；超级管理员的操作审计必须包含理由与前后状态。
- 停用后旧会话立即失效；员工不得读取未分配客资。

## 3. 合同二：唯一客资状态机与双电销任务

### 3.1 面向业务的状态

| 展示状态 | 责任人 | 允许的关键动作 | 下一步 |
|---|---|---|---|
| 草稿 | 提交人 | 编辑、删除、提交 | 待运营初审 |
| 待运营初审 | 运营 | 合格、资料不全、重复、明确无效 | 待派发 / 待电销核验 / 重复处理 / 已关闭 |
| 待电销核验 | 被派发电销 | 开始、拨号、提交事实结论 | 待运营处置 |
| 待运营处置 | 原运营或队列运营 | 入池、退回补正、重复处理、关闭、再次派发核验 | 待派发 / 补正 / 重复处理 / 已关闭 |
| 待派发 | 运营 | 选择合格公司并派发 | 已派发 |
| 已派发 | 被派发公司负责人 | 领取或等待过期释放 | 已领取 / 待派发 |
| 已领取/跟进中 | 加盟商负责人或其员工 | 跟进、成交、发起退回 | 已完成 / 退回处理中 |
| 退回处理中 | 电销事实核验、运营终审 | 核验、通过、驳回、要求补证 | 待派发 / 跟进中 / 待补证 |
| 待补证 | 原退回申请人 | 上传证据、重新提交 | 退回处理中 |
| 已完成/重复处理/已关闭 | 无 | 查看流程 | 终态 |

实现可保留既有技术枚举的兼容映射，但接口和页面不得直接以旧枚举替代上述业务状态。任何转移都必须检查当前状态、责任人、必填理由/证据、版本号或锁，并写入业务事件、审计、通知和时间线。

### 3.2 电销任务合同

| 类型 | 创建原因 | 派发人 | 电销提交内容 | 后续决定人 |
|---|---|---|---|---|
| `PRE_DISPATCH_VERIFY` | 加盟商供资或平台客资资料不全 | 运营管理员 | 联系结果、事实结论、依据、备注 | 运营管理员 |
| `RETURN_VERIFY` | 已领取客资的退回申请已提交证据 | 运营管理员 | 联系结果、事实结论、通话依据、备注 | 运营管理员 |

- 所有电销任务必须存在 `assignee_user_id` 才可开始；`PENDING` 状态只对运营队列可见，不对电销公开。
- 电销只能开始本人 `ASSIGNED` 任务；开始任务不是“领取”，不得把未分配任务写入本人。
- 运营可改派未提交任务，必须记录改派理由、原责任人、新责任人和时间。
- 前置核验与退回核验可复用 `VerificationTask`、拨号鉴权、审计和任务列表组件，但任务类型、状态前置条件、结论枚举、通知事件和业务后续处理必须独立。

### 3.3 必要测试

- 未指派电销不能查询、开始、拨号或提交任务；电销不能调用自领/改派接口。
- 前置核验结论只能进入待运营处置，不能直接入池、关闭、退款或派发。
- 退回终审在没有已提交的 `RETURN_VERIFY` 结论时必须拒绝。
- 重复提交、过期提交和并发开始必须幂等或明确冲突，不得产生两次状态变更。

## 4. 合同三：员工—派发单公司内部协作

- 公司内部协作的唯一归属对象是已领取的 `Assignment`；负责人领取后可分配、回收、转交给本公司活跃员工。
- 协作不改变运营的派发结果，也不需要运营审批或在运营列表展示个人明细。
- 员工的跟进、退回、补证查询必须以内部协作归属过滤；负责人拥有公司级可见性。
- 员工停用、负责人变更、公司停用时，未完成协作必须进入待交接，禁止自动丢弃或转给任意用户。
- 每次公司内部变更写入独立协作事件；负责人可见全量，公司员工仅见与自己有关事件，超级管理员按理由审计。

必要测试：负责人仅可操作本公司已领取派发单；员工无法访问未分配记录；运营 API 无个人协作明细；停用/转交全过程可追溯。

## 5. 合同四：积分、奖励与退回一致性

- 领取成功与积分扣减使用同一数据库事务和幂等键；失败时二者同时回滚。
- 退回终审通过时，退款、解除领取、奖励冻结/冲正、回待派发池在同一业务事务中完成，重试不能重复退款或重复冲正。
- 所有余额变化只能由不可变 `PointsLedger` 追加记录；已完成流水只能冲正，不能删除或直接修改账户余额。
- 超级管理员可直接充值、调账、规则发布、奖励处理与冲正，不需要第二位管理员复核；每次操作必须有原因、关联业务单、凭证说明、前后余额、审计与异常告警。
- 运营仅可读取派发资格所需的可用积分快照，不能调用资金写接口。

必要测试：领取并发、退回重复终审、退款失败回滚、奖励冲正幂等、每日对账差异、运营/电销资金写入拒绝。

## 6. 合同五：入口、认证、深链接与旧页退出

| 正式入口 | 允许角色 | 说明 |
|---|---|---|
| `/admin/` | 超级管理员、运营管理员 | V1.2 桌面平台壳 |
| `/h5/admin/` | 超级管理员、运营管理员 | V1.2 平台移动工作台 |
| `/h5/call/` | 电销人员 | 响应式电销工作台 |
| `/h5/` | 加盟商负责人、加盟商员工 | 响应式加盟商工作台 |
| `/call/` | 无正式角色 | 仅兼容跳转至 `/h5/call/` |

- 桌面 `/admin/` 的常驻导航只保留角色当前可执行的业务页；`内部账号`、`工作日历` 和 `加盟商治理` 收敛到“平台设置/账号中心”入口，不再暴露底层系统参数或旧版后台菜单。
- 超级管理员可从账号中心进入设置、审计和通知；运营只能看到其职责内的客资、电销、派发、异常和账号维护入口，不能因前端菜单残留获得资金或平台设置入口。
- 未登录进入受保护路径时保存目标路径，登录后只回到角色允许的页面；无权路径显示安全提示并返回该角色首页。
- 通知深链接不携带电话、积分或权限数据；进入后重新鉴权，过期/无权安全降级。
- 登出不得跳转 `index.html#/...`。新页面不得生成旧后台菜单、写入口或深链接。
- 旧页按照“迁入新页 → 只读历史/重定向 → 删除旧写入口”的映射分阶段退出，不能全局删除后再补功能。

必要测试：五角色登录落地、深链接回跳、过期会话、无权访问、`/call/` 兼容跳转、全新壳无旧 `index.html#/` 链接。

## 7. 合同六：迁移、回滚与外部验收

### 7.1 迁移流程

1. 导出现有账号、角色、公司关系、在途客资/派发/退回/任务、积分、奖励和通知快照。
2. 人工确认账号角色映射：`FINANCE → SUPER_ADMIN`、`RETURN_REVIEWER → OPERATION`；`OWNER`、`LEAD_ENTRY` 逐账号映射或停用。不得按用户名自动提权。
3. 执行 dry-run，只生成账号前后角色、公司关系、任务归属和风险项报告，不写入数据。
4. 生成可恢复备份并在预发布环境演练恢复。
5. 执行结构和数据迁移，对账角色、积分、奖励、在途任务和数量。
6. 发布窗口内保留回滚路径；未识别数据、对账差异或关键 UAT 失败均停止放量并回退。

### 7.2 上线证据

- 角色与状态机单元/集成/浏览器测试通过；权限负例、并发与幂等覆盖。
- 预发布完成数据库备份恢复、迁移 dry-run、COS 上传/读取/删除 canary、通知 Outbox 重试。
- 五角色真实账号完成两类来源客资、两类电销核验、派发领取、公司内部协作、退回终审、退款/奖励、时间线追溯 UAT。
- 微信真实通知、外部模板审核、域名与深链接验证是生产验收项，不能用模拟回调替代。

## 8. 完成定义

六项合同均有实现差距清单、测试、预发布记录和回滚说明后，才能标记“可上线”。任一合同未完成时，可以开展不改变业务状态的页面原型，但不得宣称五角色工作台或生产交付完成。
