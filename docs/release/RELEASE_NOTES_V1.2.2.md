# 合家美宅客资平台 V1.2.2 发布说明

V1.2.2 在 V1.2.1 已上线的客户反馈一至九闭环上，新增第 10 条“公海池与飞书客户视图导入”一期能力，并清理生产 Docker 网络漂移。该版本继续坚持人工派发、最小权限和可审计原则；真实飞书表、生产角色和数据容量仍必须以目标环境验证证据为准。

## 公海池一期

- 管理后台新增独立“公海池”，由超级管理员与运营人员共享维护，加盟商负责人和加盟商员工没有页面入口，接口也会拒绝访问；
- 支持完整“新增客户”表单和列表内“直接添加一行”，保存后立即计算资料完整性，未满足派发条件的记录明确显示待补字段；
- 支持运营手动触发飞书多维表格“客户视图”单向导入，每个批次统一选择进入公海池或派发池；
- 新增系统派生且不可编辑的“客户来源”：后台手填和飞书导入归为“运营录入”，加盟商供客归为“加盟商提供”；列表同时保留录入方式、渠道来源和具体提供加盟商；
- 加盟商客资审核及查重通过后，如果标准地区没有其他启用、具备接收能力且服务区域审核通过的加盟商，则暂存公海池；原提供加盟商不计入接收方；
- 使用 `app_token + table_id + record_id` 作为来源行唯一键，重复触发不会重复建档；手机号先标准化，再执行系统级查重；
- 目标为派发池时，只有姓名、手机号、标准地区、来源、授权、预算范围和查重结论全部通过的记录才进入 `READY_DISPATCH`，其余记录安全保留在公海池；
- 公海池转入派发池时重新执行完整校验，不复用导入时的旧结果；加盟商客资由运营手动重新匹配当地接收方，一期不做定时搬运；新增、编辑、导入和转池均记录操作人、结果及审计事件；
- 一期不创建定时同步任务，不调用飞书写接口，生产配置强制要求 `FEISHU_WRITEBACK_ENABLED=false`。

## 生产与交付

- 发布版本、OCI 镜像标签、环境样例、打包清单和 CI 元数据统一升级为 V1.2.2，避免复用 V1.2.1 的不可变镜像身份；
- 生产 Compose 继续使用 `zhongshu-production` 作为当前网络；历史遗留且无容器连接的 `zhongshu-lead-platform_default` 仅在现场确认后删除；
- 客户反馈第 10 条需求、飞书字段映射、部署配置和实现追踪矩阵已同步更新。

## 验收边界

- 自动化测试、静态检查、依赖审计、镜像构建和公网冒烟分别记录，不以任一单项替代生产业务验收；
- 飞书真实应用必须具备客户视图与记录只读权限，并锁定实际 `table_id`、`view_id` 和字段映射；
- 生产多角色 UAT 需覆盖超级管理员、运营、电销、加盟商负责人、加盟商员工，以及客资创建、转池、派发、领取、跟进、退回和审计查询闭环。
