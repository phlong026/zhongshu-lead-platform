# V1.2 Sprint 5 T26–T29 实施说明

## 1. 目标与范围

本 Sprint 将 V1.2 已完成的客资供给、人工派发、领取、退回申诉、后置核验、供应商奖励能力接入可操作界面，并补齐通知、报表和审计追踪闭环。

| 任务 | 交付范围 | 主要入口 |
|---|---|---|
| T26 | 加盟商 H5 全链路工作台 | `/h5/v12-workbench.html` |
| T27 | 平台管理后台全链路运营台 | `/admin/v12-operations.html` |
| T28 | 站内信、微信 Outbox、权限深链 | `/api/v1/notifications` + V1.2 业务事件投影 |
| T29 | 经营报表、审计查询、业务 ID 全链路追踪 | `/api/v1/v1.2/reports/*`、`audit-events`、`trace/{business_id}` |

## 2. T26 加盟商 H5

H5 工作台按登录用户权限动态展示：

- 公司业务总览：供应客资、接收派发、退回申诉、奖励积分、未读消息；
- 供应商客资：列表、状态、详情，并衔接既有上传页；
- 接收客资：派发单列表、详情、原子领取，领取前不展示明文电话；
- 退回申诉：草稿、截图/录音证据上传、提交、详情与终审状态；
- 供应商奖励：汇总、观察/冻结/结算/冲正明细和规则快照；
- 消息中心：未读筛选、已读标记和权限深链跳转。

入口脚本仅在账号具备相应 own 权限时注入，避免展示无权模块。

## 3. T27 管理后台

全链路运营台按 RBAC 控制菜单和操作按钮：

- 经营总览：按公司与时间范围查询 V1.2 指标；
- 供应商初审：脱敏列表、详情、通过/驳回；
- 人工派发：待派发池、候选公司资格、积分占用与幂等派发；
- 退回与后置核验：申诉详情、任务分配、平台终审；
- 奖励管理：状态查询、到期结算、单笔结算、异常冲正和规则版本；
- 审计查询：业务 ID、动作、公司、请求 ID 过滤及全链路时间线。

列表页面不显示明文手机号；只有既有受控详情接口在满足权限与业务状态时返回联系方式。

## 4. T28 通知与深链

### 4.1 事务一致性

V1.2 通知由审计后的同一业务状态变化进行投影，`Notification` 与 `NotificationOutbox` 与业务变更处于同一数据库事务。`event_key` 是跨站内信与微信发送的幂等键。

### 4.2 通知场景

- 供应商客资提交：通知供应商，并通知平台初审人员；
- 初审通过/驳回：通知供应商；通过后通知平台进入人工派发；
- 人工派发：通知接收公司待领取；
- 领取：通知接收公司，并通知供应商奖励进入观察期；
- 退回申诉：通知接收公司、后置核验人员，并冻结供应商奖励；
- 核验完成：通知退回审核人员终审；
- 终审：通知申请公司，并联动奖励取消、恢复或即时结算；
- 奖励冻结、结算、取消、冲正：通知供应商及相关平台财务/负责人。

### 4.3 深链与隔离

- 加盟商消息跳转 `/h5/v12-workbench.html?view=<target>&id=<business_id>`；
- 平台消息跳转 `/admin/v12-operations.html?view=<target>&id=<business_id>`；
- Outbox 使用 `notification_id` 精确读取对应消息，不再按“用户 + 场景的最新一条”模糊匹配；
- 公司级消息仍解析到公司主账号，平台消息按用户单独投递。

## 5. T29 报表与审计

### 5.1 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/v1.2/reports/overview` | `report.v12.read` | 平台 V1.2 全局/公司范围汇总 |
| GET | `/v1.2/reports/own` | own 权限组合 | 当前公司业务汇总 |
| GET | `/v1.2/audit-events` | `audit.read` | 多条件审计事件查询 |
| GET | `/v1.2/trace/{business_id}` | `audit.read` | 关联客资、派发、退回、奖励、核验、通知、审计时间线 |

### 5.2 数据安全

- 审计写入前递归清理手机号、密钥、令牌、Cookie 和授权信息；
- `phone_masked` 可保留用于审计辨识，明文或密文手机号统一替换为 `[REDACTED]`；
- 报表与追踪接口不返回客户明文手机号；
- 报表权限新增到 OWNER、OPERATION、FINANCE，审计查询新增到 OPERATION，超级管理员沿用 `*`。

## 6. 定时任务

每小时供应商奖励结算改由通知包装器执行：先调用既有有界批量结算，再依据最终状态生成冻结或到账通知。CLI `supplier-rewards` 与生产 Scheduler 使用同一入口，保持幂等和行为一致。

## 7. 测试与验收

- 通知/Outbox 幂等、精确消息关联和业务 ID 深链；
- 审计通知投影与敏感字段脱敏；
- OWNER/OPERATION/FRANCHISE_OWNER 报表与审计权限边界；
- 未知业务 ID 追踪返回 404；
- H5 与管理后台页面/API/权限入口静态契约；
- Scheduler/CLI 使用带通知的奖励结算入口；
- 既有全量后端回归、JavaScript 检查、密钥扫描、Python 编译、空白检查和迁移往返继续作为 PR 必过门禁。
