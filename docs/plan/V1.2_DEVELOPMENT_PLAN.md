# V1.2 开发执行计划

## 分支与合并策略

- 稳定基线：`release/v1.0.1`
- 目标集成分支：`release/v1.2.0`
- 工作分支：`feature/v1.2-<scope>`
- 每个工作包独立 PR；合并前必须完成测试、静态检查、自评审和 PR 评审。
- 推荐 squash merge；一个提交对应一个任务或一个可独立评审的修复。

## 工作包与任务

### Sprint 0 / WP0：基线、迁移和领域基础

- T00 冻结需求基线、冲突清单、追踪矩阵和开发计划。
- T01 建立 V1.2 数据库迁移骨架，新增核心字段、表、索引和约束。
- T02 实现工作日历领域服务、管理员维护/导入接口与单元测试。
- T03 新增 V1.2 状态枚举、迁移映射与状态转换守卫。

### Sprint 1 / WP1：客资供给、去重和公司能力

- T04 平台手工录入客资 API（草稿、编辑、提交）。
- T05 管理后台平台录入页面及表单校验。
- T06 手机号标准化、HMAC-SHA256 指纹与密钥配置。
- T07 去重引擎（90/180/365 天）和历史轨迹。
- T08 去重覆盖放行权限、原因与审计。
- T09 公司 `LEAD_SUPPLIER` / `LEAD_RECEIVER` 能力模型。
- T10 供应商上传 API 与公司隔离。
- T11 供应商 H5 上传、列表与详情。
- T12 供应商资料初审与直接进入 `READY_DISPATCH`。
- T13 公司级服务区域及审核。

### Sprint 2 / WP2：待派发池、人工派发和领取

- T14 待派发客资池 API 与后台页面。
- T15 候选公司筛选：区域、能力、状态、积分、自供自领、同接收方重复。
- T16 人工派发原子事务、幂等和审计。
- T17 领取扣分、联系方式解锁、工作日截止与奖励快照同事务。

### Sprint 3 / WP3：退回申诉与后置电销

- T18 四类退回原因、截图/录音 OR 证据校验和 3 工作日截止。
- T19 申诉提交后创建 `RETURN_VERIFY`，正常客资不再创建前置任务。
- T20 电销任务工作台、分配、领取、联系结果和事实结论。
- T21 管理员终审、返分、奖励冻结/取消/恢复和幂等。

### Sprint 4 / WP4：供应商奖励

- T22 奖励状态机与规则快照。
- T23 每小时结算任务、锁、幂等和账务流水。
- T24 欺诈/系统错误/管理员错误的异常冲正。
- T25 奖励比例、上下限、去重窗口和规则版本配置。

### Sprint 5 / WP5：前端集成、通知和报表

- T26 H5 全链路页面与权限入口集成。
- T27 管理后台全链路页面与字段隔离。
- T28 上传、初审、派发、领取、申诉、冻结、奖励通知与深链。
- T29 V1.2 报表、审计查询和业务 ID 全链路追踪。

### Sprint 6 / WP6：迁移、质量门禁和上线

- T30 历史手机号指纹回填和历史状态只读映射。
- T31 全量单元/集成/E2E/并发/权限/安全测试与质量门禁。
- T32 Figma 对照和真实浏览器视觉/交互评审。
- T33 UAT、灰度发布、迁移对账、回滚预案和上线复盘。

## 每项任务 Definition of Done

1. 需求编号与验收条件明确。
2. 代码、迁移、配置和文档完整。
3. 新增测试覆盖正常、异常、权限、幂等和边界。
4. 当前环境执行相关测试通过。
5. 生成 `docs/reviews/` 评审记录，包含风险、缺陷和修复结论。
6. 提交信息可追踪到任务编号；PR 描述包含测试证据。
7. CI 全绿，未发现阻断级问题，方可合并。

## 质量门禁

- Python 编译与导入无误。
- `pytest` 全量通过；关键并发/账务路径必须有集成测试。
- Alembic 可从空库和 V1.0.1 基线前向升级。
- 敏感信息扫描无明文密钥、手机号或对象存储签名。
- PR 评审无 Critical/High 未解决项。
