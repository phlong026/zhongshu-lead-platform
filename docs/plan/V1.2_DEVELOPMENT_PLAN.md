## 分支与合并策略

- 稳定基线：`release/v1.0.1`
- 目标集成分支：`release/v1.2.0`
- 工作分支：`feature/v1.2-<scope>`
- 每个工作包独立 PR；合并前必须完成测试、静态检查、自评审和 PR 评审。
- 推荐 squash merge；一个提交对应一个任务或一个可独立评审的修复。

## 每项任务 Definition of Done

1. 需求编号与验收条件明确。
2. 代码、迁移、配置和文档完整。
3. 新增测试覆盖正常、异常、权限、幂等和边界。
4. 当前环境执行相关测试通过。
5. 生成 `docs/reviews/` 评审记录，包含风险、缺陷和修复结论。
6. 提交信息可追踪到任务编号；PR 描述包含测试证据。
7. CI 全绿，未发现阻断级问题，方可合并。

## 质量门禁

- Python 编译与导入无误。
- `pytest` 全量通过；关键并发/账务路径必须有集成测试。
- Alembic 可从空库和 V1.0.1 基线在 SQLite 与 PostgreSQL 前向升级。
- 历史手机号回填可预览、断点续跑、错误脱敏和对账。
- Chromium 自动评审无可见错误、console error 或 pageerror。
- 敏感信息扫描无明文密钥、手机号或对象存储签名。
- PR 评审无 Critical/High 未解决项。
- 生产真实 UAT、恢复和灰度未签字时，状态保持 `NO-GO`。
