# V1.2 历史需求冲突与处置登记

| 历史口径/实现 | V1.2 冻结口径 | 处置 |
|---|---|---|
| 飞书作为新增客资主入口 | 平台后台手工录入 + 供应商微信 H5 上传；第 10 条一期允许运营从“客户视图”手动单向导入公海池 | 旧自动同步及回写继续停用；新增公海池入口只读客户视图、按记录 ID 幂等导入，保留 `FEISHU_LEGACY` 历史数据 |
| 正常客资派发前由电销核验 | 正常客资不前置电销 | 新流程不创建 `LEAD_VERIFY`；仅申诉后创建 `RETURN_VERIFY` |
| 自动/手动多策略派发 | V1.2 仅人工派发 | 移除/隐藏自动、随机、轮询、权重、抢单入口和任务；历史代码不得被新流程调用 |
| 48 小时申诉或奖励观察 | 统一 3 个工作日 | 使用 `calendar_days` 与 `add_workdays(claimed_at, 3)`；领取时固化截止字段 |
| 退回截图和录音双证据必传 | 截图或录音至少一项 | H5 和 API 均使用 OR 校验；两类都上传时全部保留 |
| 普通奖励先结算、申诉后冲正 | 观察期到期无申诉才结算 | 申诉期间 `FROZEN`；通过 `CANCELLED`；正常业务不使用 `REVERSED` |
| 服务区域绑定个人/自动触发派单 | 服务区域绑定公司，仅辅助人工候选 | 公司主账号维护主要城市和多区县；平台可审核；不触发自动派单 |
| `phone_hash` 作为通用哈希 | V1.2 去重采用服务端密钥 HMAC-SHA256 指纹 | 新增 `phone_fingerprint`；历史受控回填；密钥仅环境变量/密钥服务 |
| `VERIFYING/QUALIFIED/PENDING_48H` 作为当前流程状态 | V1.2 使用 `READY_DISPATCH/OBSERVING` 等新状态 | 历史只读映射；不批量改写历史事实；新数据只走 V1.2 状态机 |
| 供应商初审可能包含电话核实 | 初审只检查字段、来源、授权、权限和重复 | 初审通过直接 `READY_DISPATCH`，不得创建电销任务 |
| V1.0.1 页面与写接口继续作为默认生产入口 | V1.2 是所有新增业务事实的唯一生产写路径 | `/admin/` 默认进入 V1.2 运营台，`/h5/` 默认进入 V1.2 工作台；生产强制 `LEGACY_WRITE_ENABLED=false`，旧 `/leads`、`/verification`、`/dispatch`、`/claims`、`/returns` mutation 返回 `410 LEGACY_WRITE_DISABLED`；历史 GET 只读能力可继续按权限保留 |

## V1.0.1 生产兼容边界

- Legacy 数据和必要 GET 查询可以继续存在，用于历史追溯、迁移对账和审计；
- Legacy 页面仅通过显式 `/admin/legacy`、`/h5/legacy` 入口访问，不再作为生产默认工作台；
- production 必须设置 `LEGACY_WRITE_ENABLED=false`，该配置同时由启动前生产校验和运行时 middleware 双重约束；
- V1.0.1 mutation API 不得创建新的前置 `LEAD_VERIFY`、48 小时退回、截图+录音双证据退回、旧派发/领取等业务事实；
- 开发/测试环境可显式保留 legacy mutation，仅用于历史回归测试，不代表生产可用能力。

## 冲突优先级

1. 2026-08-06 冻结的 V1.2 PRD。
2. 本登记及 V1.2 追踪矩阵。
3. V1.0.1 中未与 V1.2 冲突的认证、权限、账务、部署、安全与人工派发能力。
4. 其他 V1.0/V1.1 历史资料。

任何新增业务书面确认若改变冻结口径，必须提升版本或形成经批准的变更单，不得直接在开发中隐式修改。
