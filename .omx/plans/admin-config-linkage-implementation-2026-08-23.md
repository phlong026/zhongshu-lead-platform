# 后台配置联动改造实施计划

日期：2026-08-23

## 目标

把后台从“输入编码和 JSON”改为“表达业务意图”，同时保持旧派发、V1.2 派发、积分账务、三工作日日历、固定 RBAC 和历史审计合同不变。

## 行为锁定

先补回归测试，再修改实现：

1. 新建加盟商自动创建积分账户、旧派发能力、V1.2 接收能力和已生效服务区。
2. 全市服务展开为当前城市下全部启用区县，避免精确地区匹配断链。
3. 充值套餐和价格规则继续使用现有版本化 API，不覆盖历史流水或派发价格快照。
4. 工作日历仍由后端按中国时区计算，历史截止时间不回算。
5. 前端不再展示飞书日常入口、角色权限矩阵、编码、原始 JSON 和手工优先级。
6. 飞书清理只删除无派发、退回或核验引用的暂存态数据，并写审计。

## 最小修改面

- 后端：新增面向后台的简化加盟商创建服务和飞书暂存预览/清理服务；保留现有接口兼容。
- 前端：定点修改 `app.js`、`points-enhancements.js`、`admin-extended-pages-v10.js` 和少量现有样式；不迁移框架、不加依赖。
- 测试：新增客户视角静态合同和后端联动测试，更新被产品决策替代的旧展示断言。

## 实施顺序

1. 先写失败测试。
2. 实现简化加盟商创建与服务区/能力同步。
3. 实现积分、账号、日历、业务选项和系统设置减法。
4. 实现飞书暂存安全清理。
5. 运行目标测试、全量测试、静态检查、安全扫描和浏览器冒烟。

## 回滚

第一阶段不删数据库字段或表。代码提交可直接 `git revert`；飞书清理接口默认只预览，执行时同时校验候选记录摘要、数量和业务引用，生产数据清理不包含在本地代码修改中。
