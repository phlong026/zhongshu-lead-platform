# V1.2 全角色界面显示优化方案（已确认并本地实施）

状态：`APPROVED / LOCALLY_IMPLEMENTED / LOCALLY_VERIFIED`

用户已确认按推荐方案改写：保留“合家美宅”品牌，借鉴“众墅之家”的参考效果与信息架构，默认不新增业务功能和新接口。本文件记录实施范围、验收标准与本地验证结论；不代表已合并、发布或完成生产验收。

## 1. 目标与推荐结论

以 `v1.2版效果图及开发文档/众墅之家_客资平台_V1.2_全页面效果图` 的 45 张页面和品牌规范为参考，在不改变业务状态机、固定 RBAC、API 路径、数据库和生产配置的前提下，优化加盟商、电销、超级管理员、老板、运营、财务、录入、退回审核等岗位的默认首页和高频页面。

推荐采用“角色首页收敛 + 高频页面重排 + 统一视觉状态”的增量方案，不做 45 页一比一重写。参考图用于借鉴信息层级、组件和视觉语言；当前用户侧品牌默认继续使用“合家美宅”，除非用户另行确认统一回“众墅之家”。

## 2. 不变边界

- 固定角色与权限以 `apps/api/src/services/rbac.py:15` 的矩阵为准，不新增可任意勾选的权限配置器。
- 正常客资不增加前置电销；电销仅处理退回后的 `RETURN_VERIFY` 事实核验。
- 保持人工派发、线下付款、人工充值、单积分账户和不可变流水。
- 加盟商领取前手机号继续脱敏；领取后仅所属公司可见；电销仅在本人任务处理阶段查看完整手机号。
- 不新增自动派发、抢单、团队排行、云外呼、自动录音、在线支付或 AI 推荐。
- 不迁移框架、不新增依赖；继续使用现有 HTML/CSS/ES Modules、`ZSIconSystem`、H5 V1.3 与后台 V1.0 设计资产。

## 3. 当前基线与实施前置

- 实施前工作分支：`feat/admin-config-linkage`，基线提交 `e52c4b9`。
- 供应商体验优化在独立分支 `fix/supplier-ux-optimization`，提交 `04c4229`，与当前分支共同修改 `apps/h5/public/v12-workbench.js`。

- 当前三套正式入口保持：加盟商 `/h5/v12-workbench.html`、电销 `/call/`、后台 `/admin/v12-operations.html`；系统配置仍从后台跳转 `/admin/index.html`。

## 4. P0：角色默认首页与导航

### 4.1 加盟商负责人 `FRANCHISE_OWNER`

涉及：`apps/h5/public/v12-workbench.js`、`v12-workbench.css`、`v12-workbench.html`，以及已在独立分支优化的 `supplier.*`。

- 底部固定为 5 个业务入口：`首页 / 客资 / 积分 / 消息 / 我的`，不再按对象顺序截取前 5 项。
- 首页首屏显示：可用积分、待领取、待跟进、退回处理中、未读消息；只保留一个最重要主操作。
- “客资”页内按权限呈现“接收客资 / 供应客资”分栏，避免两个入口割裂。
- P0 不删除现有 `supplier.html`；先由工作台分栏和入口承接供应客资，待真实浏览器验收通过后再单独评估是否收敛独立页。
- 待办卡显示：客户称呼、脱敏电话、地区、需求摘要、状态、所需积分、截止/更新时间、唯一主动作。
- “积分”复用现有 `/points/accounts/{company_id}`、积分流水和充值档位数据，不新增接口。
- “我的”集中公司资料、接单能力、供应能力、服务地区和审核说明；“加盟商设置”改为“公司资料与接单能力”。
- 供应客资提交继续复用 `fix/supplier-ux-optimization` 已完成的草稿、驳回后修改和失败恢复逻辑。

### 4.2 电销人员 `TELESALES`

涉及：`apps/call-h5/public/index.html`、`app.js`、`styles.css`。

- 首页首屏固定显示：待处理、核验中、已提交，以及“开始/继续核验”主按钮。
- 优先任务卡补齐退回原因、证据数量、处理期限和状态；不展示金额、平台收入、加盟商积分。
- 详情页首屏同时可见客户摘要、一键拨号、核验说明和填写结果入口。
- 提交后提供“继续下一条 / 返回任务列表”，保留现有领取、拨号、提交权限边界。
- 仅展示个人任务与个人统计，不增加团队排行。
- 接入现有共享 SVG 图标，删除当前 Unicode 导航占位符。

### 4.3 后台岗位默认首页

涉及：`apps/admin/public/v12-operations.js`、`v12-operations.css`、`app.js`、现有后台设计系统。

采用一个角色首页配置表和确定性优先级，不复制六套后台角色页面：

| 角色 | 默认首页 | 首屏内容 | 明确不显示 |
|---|---|---|---|
| `SUPER_ADMIN` | 系统治理总览 | 风险预警、账号角色、加盟商配置、积分规则、工作日历、通知失败、最新高风险审计 | 原始权限码、JSON 快照、无上下文技术字段 |
| `OWNER` | 老板经营看板 | 客资漏斗、派发/领取/跟进/成交、退回率、积分充值/消耗/返还、趋势与异常 | 日常录入表单和系统底层参数 |
| `OPERATION` | 今日运营工作台 | 待初审、待派发、待分配电销、待终审、加盟商能力/区域待审、通知异常 | 余额、充值、净积分变化等财务字段 |
| `FINANCE` | 积分财务工作台 | 总余额、充值/消耗/返还、人工入账、积分规则、流水与冲正入口 | 客户电话、客资详情和运营处理动作 |
| `LEAD_ENTRY` | 客资录入工作台 | 新建/继续录入、待补信息、疑似重复、最近提交 | 财务、派发和退回终审 |
| `RETURN_REVIEWER` | 退回审核工作台 | 待终审、待补证、已完成核验、截止提醒、证据摘要 | 派发、充值、账号配置 |

- 多角色账号采用安全且确定的默认优先级：`SUPER_ADMIN > OWNER > OPERATION > FINANCE > LEAD_ENTRY > RETURN_REVIEWER > TELESALES > FRANCHISE_OWNER`；其余已授权入口仍可从菜单访问。
- 角色首页优先复用现有 `/dashboard/summary`、`/dashboard/performance`、`/dashboard/trends`、`/dashboard/alerts`、各业务列表的 `total`，不伪造数据。
- 运营角色不得继续通过通用 V1.2 总览看到积分流水与净积分变化；这是 P0 必做项，不作为可选优化。优先改用已有角色化报表，同时收紧 `/api/v1/v1.2/reports/overview` 的响应投影：`OPERATION` 不返回 `points_ledger`、`net_delta`、充值、余额或收入字段，`OWNER`、`FINANCE`、`SUPER_ADMIN` 保留各自授权的财务视图；同步调整 `v12-operations.js` 的字段缺省处理，避免投影收紧后白屏；不改变路由和业务状态。

## 5. P1：六类高频页面重排

### 5.1 加盟商客资列表与详情

- 列表按“待领取 / 跟进中 / 退回中 / 已完成”分组。
- 详情按“客户信息 → 领取/跟进状态 → 时间节点 → 主动作 → 风险动作”排序。
- 领取积分、申诉截止、证据要求和完整联系方式展示条件必须与后端一致。

### 5.2 加盟商积分、消息与公司资料

- 积分页使用“余额大卡 + 本月变化 + 流水”；充值只说明线下流程和联系方式，不出现在线支付按钮。
- 消息增加未读视觉与业务类别，但深链继续使用同源白名单校验。
- 公司资料把“能否接单、为什么不能接单、哪些地区生效”放在编码/审核时间之前。

### 5.3 电销任务列表、详情与结果表单

- 列表增加状态筛选和优先任务排序；不新增后台未定义的 SLA 规则。
- 表单按“联系结果 / 事实结论 / 备注”分组，必填项清楚，提交前保留现有校验。
- 加载、空态、失败和提交成功均给下一步操作，不出现死路。

### 5.4 运营初审、派发与公司审核

- 统一为“统计摘要 + 筛选 + 表格 + 详情抽屉/弹窗”。
- 候选加盟商只展示资格、所需积分和排除原因；精确余额继续按权限隐藏。
- 公司能力与服务区域审核明确“移除审核前仍生效”。

### 5.5 退回审核

- 详情同屏展示：申诉说明、证据、电话核验结论、申诉截止和处理影响。
- 高风险按钮使用品牌化确认弹窗，替换浏览器 `prompt/confirm`，但请求、幂等和审计逻辑不变。`v12-operations.js` 已覆盖审核、派发、终审和冲正等高频动作；旧后台 `app.js` 已同步覆盖历史清理、邀请撤销、账号停用等现有危险动作。
- 证据规则保持“截图或录音至少一种”，不得沿用旧页面的“双证据必传”文案。

### 5.6 财务、账号与系统规则

- 财务页先显示对账/异常，再显示人工充值表单和流水；菜单、卡片和深链均不得把 `FINANCE` 带入客户电话或客资详情页面。
- 账号页仅显示中文岗位、状态和可执行动作，不恢复权限码矩阵。
- 系统设置保留业务默认规则、工作日历和历史清理，避免暴露 JSON、域名键名等开发字段。

## 8. 验收标准

- 8 个固定角色登录后进入正确工作面和默认首页；无权限菜单及按钮不出现，接口负例仍返回 403/404。
- 加盟商移动端首屏可看到余额或与其权限匹配的核心指标、至少 1 条待办和唯一主动作；底部导航不超过 5 项。
- 电销首屏可看到个人待处理/核验中/已提交和开始核验；详情首屏可见拨号、核验规则和填写结果入口。
- `OPERATION` 请求 `/api/v1/v1.2/reports/overview` 的响应与页面 DOM 中均不含 `points_ledger`、`net_delta`、平台余额、充值或收入字段；`OWNER`、`FINANCE`、`SUPER_ADMIN` 仅保留各自获授权的财务视图；财务页面不展示客户电话。
- 领取前手机号脱敏；领取后仅所属加盟商可见；只有任务归属电销在处理阶段可见完整手机号。
- 页面不出现原始权限码、JSON 快照、模板快照、Unicode 图标占位符和 V1.2 禁止能力文案。
- 后台列表具备统计摘要、筛选、表格、分页、状态标签和行级操作；表格正文不低于 13px。
- 390×844、iOS/Android 微信内置浏览器、1440×900 Chrome/Edge 的核心路径无横向溢出、遮挡和死路。
- 静态检查、目标前端契约测试、全量相关测试和安全扫描全部通过；本地浏览器截图通过后仍只标记 `LOCALLY_VERIFIED`，不等同生产验收。

## 9. 风险与缓解

- **品牌冲突**：参考图是“众墅之家”，当前产品是“合家美宅”。默认只复用视觉，不改品牌；品牌改名作为独立决策和独立提交。
- **双后台重复**：`admin/index.html` 与 `v12-operations.html` 有历史重复页面。P0 先确定角色入口和导航，P1 再逐步收敛重复入口，不一次性删除。
- **活跃分支重叠**：供应商分支与当前分支共同修改工作台。先合并业务修复，再做视觉与信息架构，避免回退。
- **截图与真实数据不一致**：所有指标只用真实接口；无数据展示可行动空态，不写假数据。
- **前端隐藏不等于权限**：每个可见性变更同时保留后端权限负例，不能仅靠菜单隐藏。
